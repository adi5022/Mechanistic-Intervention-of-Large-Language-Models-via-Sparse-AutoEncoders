# Cross-model transfer: step-by-step plan

Branch: `cross-model-transfer` (from `main` at `bc35482`). Written 2026-10-09. Background and reasoning: `DESIGN.md` (same folder). Earlier side note on the same idea: `docs/cross_model_patching_idea.md`. Related work (closest paper: Chen et al., NeurIPS 2025, affine residual-stream stitching between GPT-2 small and medium and others, no fact edits): `RELATED_WORK.md` (same folder; written from a summary, to be verified against the paper).

## In plain words
We edit a fact in one language model, take the change that edit made inside the model, translate it into the second model's internal coordinates, and add it there while the second model reads the same sentence. No weights change in either model. The question is whether the second model's answer moves, whether it moves for the right reason (a fact, not just a pushed word), and whether other things stay put.

The first thing to find out is whether a **translator** between two models' internal states can exist at all. Everything else depends on that, so it comes first.

## How we work through this
- You run every step in a PowerShell terminal, from the repo root `D:\Projects\transient_steering`, with the project's Python: `.venv\Scripts\python.exe`.
- I write the code for one step at a time, tell you the exact command, and you run it. Each script has `--quick` (tiny smoke run, about a minute) and prints a **RESULT** block at the end. Paste that block back and I read it with you.
- After each step I update the status table below. Nothing is committed or pushed unless you ask.
- New code goes in new files (`src/transfer/`, `tools/transfer/`). Existing code is imported and called, never edited. If a step would need a change to old code, I stop and ask.
- Outputs go to `outputs/transfer/` (a `.gitignore` inside it keeps them out of git; created in step A0).
- Pass/fail numbers ("gates") are proposals. We may revise a gate **before** looking at any later-stage result, never after.
- All times are estimates for the RTX 4050 laptop GPU (6 GB), not measurements.

## Phase B: positive control

### Step B1: swap one country for another
**Goal:** prove the whole pipeline moves a model in a known direction before any edited fact is involved.
**What it does:** for about 25 country-capital pairs, take the first model's change for "Germany" instead of "France" (at every position, token-for-token), translate it with the Gate-1 map, add it to the second model's residual stream while it reads "The capital of France is", and see whether its answer moves from Paris toward Berlin. Scale `alpha` swept over 0.5, 1, 1.5, 2, 3.
**Comparisons (all at matched size):**
- the second model's own real change for the same swap (the ceiling),
- a random vector of the same norm,
- a translated change from a *different* pair (the wrong fact),
- no translator (a random map).

**Measures:** share of pairs where the swapped answer becomes top-1; median change in its rank; effect on 12 unrelated prompts (KL divergence, top-1 flips).
**I write:** `src/transfer/inject.py`, `src/transfer/deltas.py`, `tools/transfer/03_swap_control.py`.
**You run:**
```powershell
.venv\Scripts\python.exe tools/transfer/03_swap_control.py --quick
.venv\Scripts\python.exe tools/transfer/03_swap_control.py
```
**Design as built** (`tools/transfer/03_swap_control.py`, `src/transfer/swap.py`). Prompts: "The capital of {X} is the city of" and "Everyone knows that the capital of {X} is the city of" (the plain "The capital of X is" makes both models answer "the" or "a", so small knew no capitals; these wordings force a city name: small knows 21 capitals, medium 27). A test case is an ordered pair of countries (a, b) that the **receiver** answers correctly on both. The difference "state for b minus state for a" is read in the source model at every position, translated, scaled by `alpha`, and added to the receiver's state while it reads the sentence for a. Success: the receiver's top answer becomes b's capital. Injection variants: all positions, the word's position only, the last position only. Arms: translated; the receiver's own real difference (ceiling); a random vector of the same size; a random linear map of the source difference; the translated difference of a *different* pair. `alpha` is chosen on 30% of the country pairs (dev) and reported on the other 70% (test); controls are also shown at their own best `alpha` on test, which favours the controls. Primary pairs, named before running: **Export s2m_L8_L16** and **Import m2s_L16_L8**; the other six pairs are exploratory.

**Gate 2 (fixed 2026-10-09 before the run, per direction, all-positions variant):**
- (a) the translated difference, at the `alpha` chosen on dev, makes the swapped capital the receiver's top answer on at least **20%** of test cases;
- (b) that rate exceeds the best control (each at its own best `alpha` on test) by at least **15 percentage points**;
- (c) the gain in logit difference (swapped capital minus original capital) is larger for the translated arm than for the strongest control, paired Wilcoxon test, **p < 0.01**.

Sanity checks that must hold or the run is invalid: `alpha` = 0 reproduces the unchanged model (0% success); the receiver's own difference at `alpha` = 1 on all positions gives at least 97% success (it is a state replacement, so it should be exact).
Caveat written in advance: the test cases share countries, so they are not independent; confidence intervals are indicative only.

## Phase D: Export (edit in small, transfer to medium)
Gate 2 is passed, so this can start. A 30-record pilot (`tools/transfer/04_export_pilot.py`, 2026-10-10, a look and not a result) has been run; what it showed, and how it shapes the design below, is in "Step D: pilot and analysis" at the end of this section. The numbers in "Gate 3" are PROPOSALS for the author to confirm before the controlled run, and they were written after seeing the pilot (the pilot records are excluded from dev and test).

### Step D, in plain words
A real edit is made in GPT-2 small with the project's gradient-descent tool, for example "The mother tongue of Danielle Darrieux is" -> " English" (a counterfactual target; the true answer is French). The edit changes small's internal state at layer 8, at every position, by `sum_k a_k * act_k * W_dec[k]`. We take that change, translate it with the A1 map (small layer 8 to medium layer 12 or 16), multiply by a dose, and add it to GPT-2 medium while it reads the same sentence. Then we ask four questions: (1) does medium now say " English"? (2) does it still say it when the sentence is reworded? (3) does it leave nearby facts and unrelated sentences alone? (4) is this a changed fact or just a pushed word? Question 4 cannot be answered from question 1: a plain push along the target word's own output direction makes medium say it almost every time (pilot), so the transferred edit has to be judged on questions 2 and 3 and against that push.

### Proposed design of the controlled run
- Records: CounterFact, single-token counterfactual target, neither model answers it at baseline, excluding the 100 ROME dev records and the 30 pilot records; 50 dev (choose layer and dose), 150 test (frozen first). Primary analysis on records where the edit reaches rank 1 in small (otherwise there is nothing to transfer); all records also reported.
- Maps: small 8 to medium 12 and small 8 to medium 16 only (the layers where the edit lives).
- Dose (decided by the author 2026-10-10): the main result uses the dev-split sweep (doses 0.5 to 6, chosen on the 50 dev records, reported on the 150 test records; controls at the same dose and at their own best dose). In addition one **norm-matched** dose is run as a robustness check, chosen without looking at the outcome: at every position the injected change in medium is scaled to the same share of medium's residual norm as the original edit has of small's residual norm at that position. If the two agree, the dose is not driving the result.
- Modes: relay (the same multipliers are re-applied in small to each reworded prompt and the new change is translated) and vector (one fixed change from the edit prompt).
- Measures on medium: target is the top answer; median rank of the target; same on CounterFact's paraphrase prompts; on the neighbourhood prompts (the target should not rise); on the 12 unrelated prompts (KL, top-1 flips); 20-word continuations with the transfer kept on.
- Controls at matched size: random vector; another record's translated edit; push along the target word's own output direction; edits toward rank-matched random words tuned in small and transferred; the fact stated in medium's prompt (the plain prompting baseline).

### Gate 3 (PROPOSED, to be confirmed; written after the pilot, so informed by it)
On the test records whose edit reaches rank 1 in small, relay mode, dose chosen on dev: (a) the target is medium's top answer on at least 15%; (b) that rate exceeds the best of random, another-record and rank-matched-random controls (each at its best dose) by at least 10 points; (c) paired Wilcoxon on the gain in the target's log-rank p < 0.01; (d) REPORTED, not gated: effect on paraphrase prompts as a share of the effect on the tuned prompt, and effect on neighbour and unrelated prompts against the word-push control. The word-push control is expected to beat the translated edit at top-1 (pilot); beating it is not required, but a result where the translated edit's top-1 is explained by a push (neighbour and unrelated prompts disturbed as much as the push does, paraphrase carry no better than random-target edits) is reported as "word push transferred", not "fact transferred".

- **D1. Fact sets.** CounterFact records where GPT-2 small ranks the true answer below first (the existing hard set), single-token answers only, plus counterfactual targets. Dev 50, test 150.
- **D2. Get the change.** Run the existing gradient-descent edit in small; read the change it made to small's residual stream at the chosen layer, for every prompt position. Relay mode: for each new input (a reworded prompt, each generated word), small is run with the same multipliers again and the change is recomputed and translated. Vector mode (one fixed vector from the edit prompt) is the cheap baseline.
- **D3. Inject and measure.** Add the translated change to medium. Tune layer and `alpha` on dev, freeze, run test. Measures: target rank 1 on the tuned prompt; reworded prompts; neighbour prompts; the 12 unrelated prompts; 20-word generations with the transfer kept on; edit size as a share of medium's residual norm; transfer efficiency (effect in medium divided by effect in small).
- **D4. Controls (all at matched size):** random vector; a push along the target word's own output direction in medium (if this does as well, the word transferred, not the fact); no translator; rank-matched random targets; the fact stated in medium's prompt; medium's own gradient-descent edit if we port it (the ceiling).

### Step D: pilot and analysis (2026-10-10; 30 CounterFact records, no split, no gate; `packs/cross_model_transfer/d_pilot.json`)
- The gradient-descent edit reaches rank 1 in small on 17 of 30 counterfactual targets (median start rank 315, median same-prompt KL 0.92, edit size at the last position 29% of the residual norm).
- **89% of the edit's squared size is at positions between the start token and the last token (the subject and relation words); 5% is at the last position.** [WITHDRAWN 2026-10-10: the sentence that followed here, that the multiplier edit is mainly a change of the subject's representation, is not supported: those positions include the relation words, and an edit restricted to the subject's tokens alone reaches rank 1 on only 12% of records (59% for all positions); Entry 32 section 3.6.] This is where B1 found the translator strongest (the word's position) and the last position weakest, so the edit lives where the channel is best. It is also compatible with an association edit (ROME's locus is the last subject token) but does not show one: that is Phase C.
- Transfer to medium (medium's median rank of the target before anything: 165). Small 8 to medium 16, target is medium's top answer / median rank: translated 0, 2, 6, 5 of 30 / 25, 21, 23, 89 at doses 1, 2, 3, 4; random vector 0, 1, 1, 1 / 159 to 560; another record's edit 0 of 30 / 179 to 611; push along the target word's output direction 5, 26, 28, 30 of 30 / rank 3 then 1. - Reading: the translated edit does something real (rank 165 to about 22, top-1 up to 20%, controls 0 to 3%), but it is far weaker than a trivial push, and it degrades at the highest dose (the translated change is off the map's training distribution). Success at top-1 alone cannot separate fact from word push, which is why Gate 3 is judged on controls, paraphrases, neighbours and unrelated prompts.

### Step D5: inject at several layers of medium (idea 1 after the failed Gate 3; gate written 2026-10-10 BEFORE the run)
**Question.** The edit is made in small at layer 8 and was added to medium at one layer at a time (12 or 16). Does adding the same translated change at several layers of medium at once make it land better than the best single layer? (Also: layers 4, 8 and 20 were never tried for the real edit.)

**Design.** Same 200 records, same recipes, same linear maps (small 8 to medium 4, 8, 12, 16, 20), new tool `tools/transfer/10_multilayer_export.py` (new code only). Configurations: five single layers (4, 8, 12, 16, 20) and five layer sets (12+16, 8+12+16, 12+16+20, 8+12+16+20, 4+8+12+16+20). In a layer set the dose is SPLIT: each layer gets dose/n of its own translated change, so the total budget equals a single-layer dose and any gain is not just a harder push. An unsplit variant (every layer gets the full dose) is run as an exploratory extra and cannot satisfy the gate. Doses 0.5 to 6 (as in D3), chosen per configuration on the dev records whose edit reached rank 1 in small (top-1 rate, then mean log-rank gain, then smaller dose); one outcome-free norm-matched dose per layer as a robustness check. Arms: translated, random vector (same size per position and layer), wrong recipe (another record's edit). Stage 2 (rewordings, neighbours, unrelated prompts) is run on test records for the dev-selected best single layer and best layer set only.

**Gate 4 (fixed before the run).** Evaluated on the test records whose edit reached rank 1 in small. "Best single" = the single-layer configuration with the highest dev top-1 (tie: dev mean log-rank gain); "best set" = the same for the five split layer sets; both chosen on dev, reported on test.
- (a) best set's test top-1 is at least 10 points above best single's test top-1;
- (b) paired Wilcoxon on the gain in log-rank of the target, best set against best single, p < 0.01;
- (c) best set's test top-1 is at least 15% and at least 10 points above both its random-vector and wrong-recipe controls (each at its own best dose on test, which favours the controls).
Pass = (a), (b) and (c). Failing means: adding the change at several layers does not rescue the export, and the layer is not the bottleneck.

**Rerun bar (PROPOSED by Claude, not yet confirmed by the author; reported, not gated, for the best configuration of this run):** the export counts as working only if top-1 is at least 50% on those records, the rewordings lift ("new beats true") is at least 80% of the lift the edit itself gives in small, and the neighbours score (true still beats new) falls by at most 5 points against unchanged medium. The 15% floor of Gate 3 was a minimal "something above the controls" line, not a "works" line.

### Step D6: the ceiling test, tune the edit through the translator (gate written 2026-10-10 BEFORE the run)
**Question.** Every export so far used an edit tuned to move small. Can the channel (small's SAE features at layer 8, linear map, medium layer 16) carry an edit that reaches rank 1 in medium at all? If an edit tuned directly against medium's output through the translator cannot, the channel (not the choice of edit) is the limit. If it can, the next question is whether it carries to rewordings and spares neighbours, or is only a push on the tuned prompt. NOTE: this tunes against B's output, so a pass shows a ceiling, not a clean transfer; it needs no SAE on medium (the multipliers are still on small's features).

**Design.** `tools/transfer/11_b_aware_edit.py`, `src/transfer/b_aware_edit.py` (new code only; `src/gradient_editing.py` is imported, not edited). For each of the 150 test records: the same 200 candidate features and the same multiplier parametrisation, loss and settings as the original edit (100 steps, lr 0.1, KL weight 3.0, size weight 0.005, margin 0.3, start at no edit), except that the forward pass is small's change at layer 8, times the A1 linear map small 8 to medium 16, times a fixed dose of 2.0 (the dose chosen on dev in D3 for this layer; not re-tuned), added to medium's layer 16, and the loss (rank hinge and KL) is measured on MEDIUM's last-position logits. Injection layer 16 and dose 2.0 are fixed before the run; no dev records are used. The recipe is then judged through the same hook path as every other export run. Controls: a tuned edit toward the record's rank-matched random word (judged on that word); another record's tuned recipe; the original small-tuned recipe at the same dose (reference, 8% top-1 before). Relay mode on rewordings, neighbours and the 12 unrelated prompts exactly as in D3.

**Gate 5 (fixed before the run), on the test records whose original edit reached rank 1 in small (88, for comparison with D3 and D5); all 150 are also reported:**
- (a) the tuned recipe makes the target medium's top answer on the tuned prompt on at least **50%** of records;
- (b) rewordings: the lift in "new beats true" over unchanged medium is at least **80%** of the lift the original edit gives inside small on the same records (measured in the same run);
- (c) neighbours: the "true still beats new" score falls by at most **5 points** against unchanged medium.
Readings fixed in advance: all three hold = the channel can carry a rank-1 edit that generalises (go to the step that removes the per-record tuning on B: translator trained on edits); (a) holds but (b) or (c) fails = the channel carries a push on the tuned prompt but not a generalising change (steering); (a) fails = the channel cannot carry a rank-1 edit within this feature family (the limit is the map, or the family). Reported, not gated: the same numbers for the random-word edit tuned the same way (what any word can do), the wrong recipe, the original small-tuned recipe, unrelated-prompt disturbance, and the edit's size as a share of medium's residual norm.

### Step D7: a translator trained on edits with an output-matching loss (gate written 2026-10-10 BEFORE the run)
**Question.** D6 showed the channel can carry a rank-1 edit when the dials are tuned per sentence against medium's output. Can ONE trained map carry edits that were tuned only in small (so nothing is tuned on medium at test time)? The ridge map was fitted to reproduce states on ordinary text; this map is trained to make medium's answers change the way small's answers change under an edit.

**Design.** `tools/transfer/12_output_matching.py`, `src/transfer/output_matching.py` (new code only).
- *Training data (disjoint from every evaluation record):* about 800 further CounterFact records (seed 2), single-token counterfactual targets, neither model answering the target, excluding the 100 ROME dev records, the 30 pilot records and all 200 benchmark records; and, so that the map cannot just learn word-level pushes, **excluding every record whose counterfactual target word is the target of any dev or test record**. The original gradient-descent edit is tuned in small for each (same tool, same 200 candidate features and settings as D2); only edits that reached rank 1 in small are used for training. For each such record the recipe is re-applied (relay) to the tuned prompt, 2 rewordings and 2 neighbour prompts, so the map also sees how the edit behaves off the tuned sentence.
- *Map:* linear, small layer 8 to medium layer 16, started at the ridge solution W0 (A1), trained with a small penalty for moving away from W0.
- *Loss:* for each text, goal = log-softmax(medium's clean logits + (small's edited logits minus small's clean logits)), i.e. "medium's answers should move by the amount small's moved" (both models share one vocabulary); loss = KL(goal || medium's logits after adding the translated change). Zero loss at no edit. Nothing about the evaluation records is used.
- *Selection on the 50 dev records (their small-tuned edits, rank 1 in small):* the epoch with the highest mean log-rank gain of the target in medium at dose 1; then the dose from {0.5, 1, 1.5, 2, 3} by dev top-1 rate, then mean log-rank gain. Fixed: injection layer 16, 15 epochs, Adam lr 2e-4, batch 32, weight 0.1 on the relative-distance penalty.
- *Evaluation:* the 150 test records, primary = the 88 whose original edit reached rank 1 in small; the **same original small-tuned recipes as D3**, injected through the trained map. Arms: trained map (chosen dose); ridge map at dose 2.0 (the D3 reference, 8%); trained map with another record's recipe; trained map with the rank-matched random-word edit (judged on that word). Relay on rewordings, neighbours, unrelated prompts as in D3.

*Actual training set (recorded 2026-10-10 during the run; the gate below never fixed a training size, so it is unchanged):* of 1,450 candidate records, 829 were dropped by the held-out rule (target word or subject shared with a dev or test record), 621 were edited in small, and the edit reached rank 1 on 289 of them (47%; the benchmark records gave 58%); the 289 gave 1,445 training texts. The "about 800" above was the requested size.

**Gate 6 (fixed before the run), on the 88 primary test records:**
- (a) top-1 on the tuned prompt at least **50%**;
- (b) rewordings: lift in "new beats true" over unchanged medium at least **80%** of the lift the edit itself gives inside small (measured in the same run);
- (c) neighbours: the "true still beats new" score falls by no more than the edit's own fall inside small (D3 and D6 measured 9 points on these records; recomputed in the run). Note: this reference (instead of the 5-point line of Gate 5) was chosen after seeing D6; the author can veto it before the run.
Readings fixed in advance: all three hold = one trained map carries a small-tuned edit into medium with no tuning on medium (the export result); (a) holds but (b) or (c) fails = a push on the tuned prompt; (a) fails = output matching with this map and data does not rescue the export, and the amount of improvement over the ridge map (8% top-1) is reported with a paired test on the log-rank gain. Reported, not gated: the same numbers for the wrong-recipe and random-word arms, unrelated-prompt disturbance, D6 (95%) as the ceiling.

*Result (recorded after the run, 2026-10-10):* Gate 6 FAILS on (a) 18% and (b) 0.74; (c) holds. The trained map improves over the ridge map (8% to 18%, median rank 14 to 7). See the results log.

### Step D8: does the map trained on edits improve with more training data? (a diagnostic; rule written 2026-10-10 BEFORE the run)
**Question.** D7 (Gate 6 failed) used only 289 training edits and its loss was still falling. Before spending hours generating more edits, check whether the result rises with the amount of training data, using only data we already have.

**Design.** `tools/transfer/14_datasize_check.py`, `src/transfer/om_batched.py` (new code only). A batched version of the D7 training (all texts padded to one length and run through medium together; checked against the one-text-at-a-time D7 code: per-text KL differs by about 3e-6, the gradient on the map has cosine 1.000000, and an epoch takes about 7 s against 93 s). The map is trained with the D7 settings (15 epochs, Adam lr 2e-4, batch 32, penalty 0.1 towards the ridge map, same training texts) on 25%, 50% and 100% of the 289 training edits, 3 seeds each (a different random subset per seed for the fractions below 100%; the seed also changes the batch order). For every run the epoch is chosen on the 28 dev records, the dose on the dev records from {0.5, 1, 1.5, 2, 3}, and the tuned-prompt result is read on the 88 primary test records (150 also reported) with the same small-tuned recipes as D3 and D7. The 100% run with seed 0 should replicate D7 (top-1 18%, median rank 7); if it does not, the batched code is suspect.

**Decision rule (fixed before the run).** Using the primary records, means over the 3 seeds: if (i) top-1 at 100% is at least **4 points** above top-1 at 50% **and** (ii) the mean log-rank gain of the target rises from 25% to 50% to 100%, the curve is RISING and more training edits are worth generating; if neither holds it is FLAT and more data will not rescue this map; otherwise UNCLEAR (reported with the numbers). It is a diagnostic, not a gate on the method: it says nothing about the 50% bar of Gate 6, and two or three points on one training pool with noisy test records (one record is about one point) are a crude trend.

*Result (recorded 2026-10-10):* the 100% seed-0 run replicated D7 (18%, median rank 7). Primary top-1, mean over 3 seeds (range): 25% of the edits (72 records) 13% (12 to 14%), 50% (144) 13% (9 to 17%), 100% (289) 20% (18 to 20%); mean log-rank gain 2.34, 2.35, 2.66 (ridge map reference: 8% and 2.04). By the rule fixed above: **RISING**. Caveats: the curve is flat from 25% to 50% and then jumps; the three seeds at 100% use the same data and differ only in batch order, so their narrow range understates the noise; at 100% the best epoch on dev was the last one (15) in all three seeds, so training may have stopped early (step D9). The median-rank column of this tool uses the lower of the two middle values for an even count (the other tools use the upper one; the ridge reference shows 12 here and 14 in D3); top-1 and the gain, which the rule uses, are not affected. The code now uses the upper median, the saved `d8_datasize.json` the lower one. Data: `packs/cross_model_transfer/d8_datasize.json`.

### Step D9: does longer training help? (rule written 2026-10-10 BEFORE the run)
**Question.** At 100% of the 289 edits the best epoch on dev was always the last one (15) and the training loss was still falling (D7, D8). Is the map simply undertrained?

**Design.** The same tool (`tools/transfer/14_datasize_check.py --fractions 1.0 --epochs 40 --longer --tag longer`): the map trained on all 289 edits for **40 epochs** instead of 15, 3 seeds, everything else as in D7 and D8 (Adam 2e-4, batch 32, penalty 0.1, epoch chosen on the 28 dev records by dev mean log-rank gain, dose chosen on dev, result read on the 88 primary test records with the same small-tuned recipes).

**Rule (fixed before the run).** Compared with the 15-epoch runs of D8 at 100% (mean top-1 20%, mean log-rank gain 2.66): **LONGER TRAINING HELPS** if the mean top-1 over the 3 seeds is at least **4 points higher** AND the mean log-rank gain at least **0.10 higher**; otherwise NO REPRODUCIBLE IMPROVEMENT FROM LONGER TRAINING. Reported: the epoch chosen per seed, the dev trace, the 150-record numbers. A lower training loss alone does not count. Like D8 this is a diagnostic: it says nothing about the 50% bar of Gate 6.

*Result (recorded 2026-10-10):* NO REPRODUCIBLE IMPROVEMENT FROM LONGER TRAINING by this rule: top-1 2% against 20%, mean log-rank gain 1.81 against 2.66, dose 1.0 chosen on dev in all three seeds (epochs 40, 36, 34). The verdict stands; step D9b shows the drop was an artefact of the dose rule. Log: `packs/cross_model_transfer/logs/d9_longer_training.log`.

**What follows.** If longer training does not help, the next tests are a rank-1 term in the loss (D10; it may turn the map into a better steering mechanism without making it a better transfer mechanism, so neighbours and the random-word control must be watched) and a small neural map with the same loss (D11; an earlier neural translator trained on text fitted better but exported no better, so expectations are modest). Each gets its own rule written before its run. More training edits (the expensive step, about 3 s per edit) only if the earlier tests justify it.

### Step D9b: a post-hoc look at the dose in the longer-training test (written 2026-10-10 while D9 was still running; POST-HOC, not a gate)
**Why.** In the first D9 seed (40 epochs) the dev curve improved slowly (dev gain 1.64 to 1.71, dev median rank 18 to 15), but the dose rule (the dose with the most dev records having the target on top, then dev gain, out of only 28 dev records, so one record is 3.6 points) chose dose 1.0, and at dose 1.0 the test result was 2% where the 15-epoch maps at dose 2.0 had given 18 to 20%. The D9 verdict by its pre-set rule stays the verdict; this step only shows what the dose was doing, and it was designed after seeing that, so it is exploratory.

**Design.** `tools/transfer/15_dose_table.py`, `src/transfer/om_batched.py` (`train_map_horizons`), new code only. For each of 3 seeds one run of 40 epochs on all 289 edits (batched, D7 settings); the 15-epoch map is the best epoch among the first 15 of the same run (identical to a run that stops at 15 with that seed). For every map and every dose in {0.5, 1, 1.5, 2, 3}: dev (28 records) and test (88 primary records) top-1, gain and median rank. Three ways to pick the dose are compared: (A) the D7/D8/D9 rule, (B) the dose with the best dev mean log-rank gain, (C) a fixed dose of 2.0. The test numbers at every dose are descriptive and not used to choose. Check: the 15-epoch maps under rule A should reproduce D8 (18%, 20%, 20%).

**How it will be read (fixed before the run).** Descriptive only: under each dose rule, does the 40-epoch result beat the 15-epoch result by at least 4 points of top-1 and 0.10 of mean log-rank gain (the D9 thresholds)? If under rule B or C it does and under A it does not, the D9 verdict "no improvement" is reported as an artefact of the dose rule, with the numbers; if it does under none, training length is not the limit. Either way this is not a pass or fail of the method (the 50% bar of Gate 6 is unchanged) and one training pool with 88 test records is a crude basis.

*Result (recorded 2026-10-10):* the 15-epoch maps under rule A reproduce D8 (18%, 20%, 20%). With rule B or C the 40-epoch maps give 20% (19 to 20%), gain 2.61, against 20% and 2.66 at 15 epochs: the difference is 0 points and -0.05 gain, so under no dose rule does longer training help by the D9 thresholds, and under B and C it does not hurt either; under rule A the 40-epoch maps get 2% because dev (3 of 28 records) preferred dose 1.0, where the test result is 2%. Training loss kept falling (0.21 to 0.06). **Protocol change from D10 on: the dose is chosen by the best dev mean log-rank gain (rule B).** Data: `packs/cross_model_transfer/d9b_dose_table.json`; log `logs/d9b_dose_table.log`.

### Step D10: a rank-1 term in the training loss of the map (design, gate and procedure written 2026-10-10 BEFORE the build and the run; confirmed by the author)
**Question.** D7 to D9b: a single linear map trained to make medium's answers shift the way small's shift reaches about 20% top-1 and has plateaued (more epochs do not help). D6 reaches 95% because its loss says directly "make the target the top answer". Does adding that instruction to the TRAINING of the map (so that nothing is tuned on medium for a new sentence) let the map carry edits it has never seen to rank 1?

**What stays the same as D7/D8/D9b.** The same 289 training edits (1,445 texts: the tuned prompt, 2 rewordings, 2 neighbours per record; the held-out rule: no target word or subject of any dev or test record), the same linear map small 8 to medium 16 started at the ridge solution, the same output-matching KL loss, Adam 2e-4, batch 32, penalty 0.1 towards the ridge map, training dose 1.0, 15 epochs (D9b: 15 equals 40), 3 seeds (0, 1, 2; the seed shuffles the batches), the same dev records (28, choose) and test records (88 primary, 150 all, read), the same small-tuned recipes at test time.

**What is added.** To the loss of every TRAINING text that is a tuned prompt (one per record, 289 in all; never rewordings or neighbours, where the target must not be forced to win): `lambda * relu(0.3 - (target logit - strongest other logit))` on medium's last-position logits after the injection, the same hinge and margin as the original edit and D6. The loss per text is `KL + lambda * hinge` (the hinge only on tuned prompts), averaged over the batch.

**The weight lambda (wider grid, as the author allowed).** 0 (the D8 baseline in the same sweep: it must reproduce top-1 near 20%), 0.01, 0.03, 0.1, 0.3, 1.0.

**Selection (all on the 28 dev records, never on test; dose protocol as changed after D9b).** Per run: the epoch with the best dev mean log-rank gain at dose 1 (as in D7); then the dose from {0.5, 1, 1.5, 2, 3} with the best dev mean log-rank gain (ties: the smaller dose). The run's dev score is its dev mean log-rank gain at that dose. **lambda-star** = the lambda with the highest dev score averaged over the 3 seeds (ties: the smaller lambda). All lambda are also reported on test, descriptively.

**Controls (every run, at the tuned prompt on the test records).** Another record's recipe through the same map (expected 0%) and the edit toward the record's rank-matched random word, judged on that word (the specificity control: if it succeeds as often as the real target, the map is a steering tool).

**Judging (for lambda-star and for lambda = 0, all 3 seeds each, at their chosen doses).** The recipes are re-applied (relay) to the rewordings (2), neighbours (5) and the 12 unrelated prompts of each test record: PS (new beats true on rewordings), NS (true still beats new on neighbours), unrelated KL and top-1 flips; the references (medium unchanged, small unchanged, small with the edit) are the numbers already measured in D7 on the same records.

**Gate 7 (fixed before the build and the run), on the 88 primary test records, the mean over the 3 seeds of lambda-star:**
- (a) top-1 on the tuned prompt at least **50%**;
- (b) rewordings: the lift in "new beats true" over unchanged medium is at least **80%** of the lift the edit gives inside small (27 points in D7);
- (c) neighbours: the "true still beats new" score falls no more than the edit itself does inside small (9.5 points in D7);
- (d) specificity: the real target's top-1 exceeds the random-word edit's (judged on its own word) by at least **10 points**.
**Readings fixed in advance:** all four hold = one trained map carries edits it has never seen into medium with no tuning on medium and is specific to the target; (a) holds but (d) fails = the map has become a steering mechanism (it pushes whatever word the edit points at); (a) holds, (d) holds, (b) or (c) fails = a push on the tuned prompt that does not generalise; (a) fails = a rank-1 term does not rescue the export with this map and data. In every case reported: improvement over lambda = 0 in the same sweep (paired Wilcoxon on the per-record log-rank gain, 88 records, seed-averaged), per-seed numbers, all lambda on test.

**Procedure and cost.** New code only: `src/transfer/om_batched.py` (`train_map_hinge`), `src/transfer/om_judge.py` (batched relay judge), `tools/transfer/16_rank1_term.py`. The tool prints progress for every run, saves its log (`outputs/transfer/logs/`) and a JSON with the per-epoch curves, per-dose tables, per-run controls and the judging. 6 lambda values x 3 seeds = 18 runs of about 80 s each (about 25 minutes), plus about 3 minutes to build the judge items (cached) and about 2 minutes of judging. The author runs it in their own terminal (`$env:HF_HUB_OFFLINE=1; .venv\Scripts\python.exe tools/transfer/16_rank1_term.py`); a `--smoke` option runs a one-minute rehearsal. After the run: journal entry, figures from the saved data, `PAPER_NOTES.md`, logs, push.

**Risks written down beforehand.** (1) Steering instead of transfer: handled by control (d) and the random-word arm. (2) Overfitting to 289 target words: the test targets are held out, so it shows as a low test result. (3) Neighbour damage: condition (c). (4) The 28 dev records are a noisy guide to lambda and dose: all lambda are reported on test too, and the primary result is fixed to lambda-star by the rule above. (5) A pass would still rest on 3 seeds sharing one training pool and 88 test records and would need replication before any claim.

*Result (recorded 2026-10-10):* **Gate 7 FAILS.** The best mean dev score was at lambda 0 (2.53, falling to 2.13 at lambda 1.0), so lambda-star = 0 and the D7 baseline was judged: (a) 20% against 50% NO, (b) 0.74 against 0.8 NO, (c) neighbours fall 7 points against 9.5 ok, (d) real minus random-word 14 points against 10 ok. Reading: a rank-1 term does not rescue the export with this map and data. The lambda = 0 row reproduces D8 and D9b. On test lambda 0.1 and 0.3 give 21% and lambda 1.0 gives 16% (all within or below the baseline seed range); the training shortfall from rank 1 falls from about 2.4 logits (lambda 0) to about 0.15 (lambda 1.0): the map learns the training targets but not unseen ones. Data: `packs/cross_model_transfer/d10_rank1_term.json`; log `logs/d10_rank1_term.log`.

### Step D6b: how different is D6's solution from the original edit? (a descriptive diagnostic; rule written 2026-10-11 BEFORE the run)
**Question.** The edit tuned in small reaches rank 1 in medium on only about 20% (best trained map), while the same 200 SAE dials re-tuned against medium's output (D6) reach 95%. Is D6's solution close to the original edit in direction (so that a different strength or a better map could fix the export), or is it a different direction (so that the original edit does not contain what medium needs, and only changing the edit side can help)?

**Data and measures (no training; small and its SAE are only used to recompute the layer-8 changes).** On the 150 test records, the original recipe (`d_edits.pt`) and D6's recipe (`d6_recipes.pt`) have the same 200 features (D6 started from the original's candidate set). For each record: the two dial vectors (cosine, Pearson correlation, sign agreement among the dials that matter, size ratio) and the two injected changes in medium's layer-16 space (ridge map times dose 2.0): cosine at the last position, cosine over all positions but the first, the share of D6's last-position change that lies along the original's direction (cosine squared) and the size ratio. Chance levels: the cosine between D6's last-position change and another record's original change, and between D6's changes of two different records (a common direction shared by all edits would show there). Reported as medians with quartiles on the primary records whose D6 tuning reached rank 1 at training time (and on all D6-successful test records).
**Reading rule (fixed before the run), on the median last-position cosine between D6's change and the translated original (primary records):** at least 0.5 = the same direction with a different strength (a dose or map fix is plausible); from 0.2 to 0.5 = partly the same direction; under 0.2, close to the chance levels = a different direction: the original edit does not contain what medium needs, so a map alone cannot fix it, which favours changing the edit side (more varied training edits, amortised D6). A descriptive diagnostic: it is not a gate on a method.

*Result (recorded 2026-10-11):* D6b (how different is D6's solution from the original edit? 84 primary test records where D6 reached rank 1 in training): median cosine at the last position 0.51 (quartiles 0.25 to 0.70; chance 0.02 and 0.05), all positions but the first 0.26, dial vectors 0.27 (sign agreement 0.62), D6's change is 0.71 of the original's size and its best scalar multiple of the original's direction is 0.35. By the rule fixed beforehand (at least 0.5 = same direction, different strength) the median just meets the top bucket; read with the spread and the lower all-position agreement it is partly the same direction and partly new, and D6 is smaller, not a harder push. Data: `packs/cross_model_transfer/d6b_compare.json`; log `logs/d6b_compare.log`; Entry 33 section 4.8.

### Step D13: a map trained on many more, and more varied, edits (synthetic targets) (design, gate and procedure written 2026-10-11 BEFORE the build and the run; the gate repeats Gate 7 unchanged)
**Question.** D7 to D10: the map trained on 289 edits memorises its training target words (95% top-1 on them, 16% on unseen words) and plateaus at about 20%; D6b: D6's solution is only partly in the direction of the original edit. The diagnosed weakness is a lack of variety. Does a map trained on many more edits, with target words that vary widely, carry unseen real counterfactual edits better?

**Where the extra edits come from (`tools/transfer/21_varied_edits.py`, new code).** The edits are made exactly as before (the project's gradient-descent tool in small, 200 candidate features at layer 8, 100 steps, all positions; only edits that reach rank 1 in small are used). Sentences: the D7 pool (1,450 CounterFact candidates, seed 2, already excluding the ROME dev, pilot and all benchmark sentences) minus any sentence whose subject is the subject of a dev or test record (the subject hold-out of D7 is kept). Targets: for every sentence **2 random words** instead of its counterfactual target: single-token alphabetic words (leading space, longer than 3 characters) whose rank on the prompt in small is within 0.7 to 1.4 times the rank of the sentence's own counterfactual target (widened to 0.5 to 2 and 0.3 to 4 if none), excluding the sentence's true and counterfactual words and **every true or counterfactual word of any dev or test record**, so no evaluation word is ever a training target. The 289 real-target edits of D7 stay in the training set. About 2,800 attempts at about 3 s each; the tool runs 3 worker processes on the GPU in parallel (about one hour; resumable; each worker saves its own shard and log; the parent merges them into `d13_edits.pt`).

**Training and evaluation (`tools/transfer/22_varied_training.py`, to be built while the edits are generated).** As in D7 to D10: the same linear map small 8 to medium 16 started at the ridge solution, the D7 output-matching KL loss (no rank-1 term: D10 showed no benefit), Adam 2e-4, batch 32, penalty 0.1, training dose 1.0, 15 epochs, 3 seeds; training texts for every edit: the tuned prompt, 2 rewordings and 2 neighbours of the sentence; epoch and dose chosen on the same 28 dev records by dev gain; judged on the same test records with the same small-tuned real recipes (88 primary, 150 all), with the same controls (another record's recipe, the random-word edit) and the same relay on rewordings, neighbours and unrelated prompts. **Data curve:** training sets = the 289 real edits only (replicates D7 to D10), plus 25%, 50% and 100% of the synthetic edits (random subsets by seed). The primary result is the full set.

**Gate 9 (the four conditions of Gate 7, unchanged), on the 88 primary test records, mean over 3 seeds, full training set:** (a) top-1 at least **50%**; (b) rewordings lift at least **80%** of the lift the edit gives inside small (27 points in D7); (c) neighbours fall no more than the edit itself does inside small (9.5 points); (d) the real target's top-1 at least **10 points** above the random-word edit's (judged on its own word). Reported: the improvement over the real-289-only baseline in the same sweep (paired Wilcoxon on the per-record log-rank gain), top-1 on the training prompts against top-1 on the unseen test records (the overfitting check of D10), and the data curve.
**Readings fixed in advance:** all four hold = a map trained on varied edits carries unseen real edits; (a) fails but the test top-1 rises by at least 5 points above the baseline's and the gap between training and test top-1 shrinks = variety helps but not enough (next: a regularised neural map on this set); (a) fails and the test top-1 stays within 5 points of the baseline = the variety of target words was not the limit (the limit is the edit or the map: amortised D6, or stop); if the random-word edit's top-1 rises as much as the real target's, the map has learned to push any word (reported as that).

**Risks written down beforehand.** (1) Random words are not plausible counterfactuals, and edits toward them may differ in character from real ones (in D2 the random-word edit reached rank 1 on 44% against 58% for the real target); the controls and condition (d) watch for a push-any-word map. (2) Edit tuning takes about an hour even in parallel. (3) The three seeds share one training pool. (4) More data may help only a little (D8 hinted at a noisy rise).

*Generation result and one exploratory arm (recorded 2026-10-11, after the edit generation and BEFORE the training run; the gate and the readings above are unchanged).* The generation finished in 3,542 s with 3 workers: 2,894 edits attempted (1,447 sentences x 2 random words, none skipped), **1,221 reached rank 1 in small (42%)**, on 749 sentences, toward **759 distinct target words** (the 289 real edits cover only **116** distinct words, and 38 of them are also among the synthetic words); none of the target words is a true or counterfactual word of any dev or test record (198 banned). The success rate depends strongly on how far the word starts in small: 93% below rank 50, 64% at 50 to 150, 42% at 150 to 400, 24% at 400 to 1,000, 6% beyond. The synthetic edits are therefore easier than the real ones: median start rank 54 (quartiles 16 to 194) against 116 (33 to 433) for the real training edits and 105 (36 to 292) for the test records. To see whether that mismatch matters, `22_varied_training.py` gets **one exploratory training set**: the real edits plus only the 457 synthetic edits whose target starts at rank 100 or worse in small (deterministic subset, 3 seeds); it is reported in the data curve and is not the primary result (the primary result is still the full set, judged by Gate 9). Data: `packs/cross_model_transfer/d13_edits_summary.json`; log `logs/d13_varied_edits.log`.

Starts after Phase D has a first reading. Details to be filled in.

- **E3. Inject only the decoded difference of the accepted features. The receiver is **never told the answer** in these arms. A target-aware arm (`causal`) is secondary and needs its own control.
- **E4. Same controls as D4.**

### Steps E2 to E4: the Import experiment (design and gate PROPOSED 2026-10-10 BEFORE the build; revised the same day after the author's comments; gate numbers CONFIRMED by the author on 2026-10-10)
**Revision note.** The first draft had an SAE-filtered change as the primary arm and a 20% bar. The author argued that (1) 20% is too low a bar, (2) replacing the residual stream is the better primary arm (medium's stream is the stronger one; the open question is how much of it survives in small, and whether small also inherits medium's mistakes), and (3) steering small with medium's data, with no SAE on medium, is itself a result even without knowledge transfer. Changes: the primary arm is now replacement, the rescue bar is 50%, and the agreement of small's answers with medium's (right or wrong) is measured as a separate steering result.

**Question.** Medium knows 780 true facts that small gets wrong (E1). If small reads a sentence with its layer-8 state replaced by medium's layer-16 state, translated into small's coordinates (small's own last four layers then run as normal), without ever being told the answer, how many facts does it get right, what does it break, and how much of medium's behaviour does it take over? Nothing is trained and no weight changes; the translator is the A1 map; there is no SAE on medium.

**Setup.** Donor: medium's `blocks.16.hook_resid_pre`; receiver: small's `blocks.8.hook_resid_pre`; translator: the A1 ridge map `m2s_L16_L8` (per-dimension R-squared 0.66; on ordinary text stitching recovers 98%: loss 4.31 stitched against 4.24 small alone and 3.96 medium, so the stitched model is expected to behave closer to small than to medium). Facts: all 21,789 single-token CounterFact facts outside the ROME dev and pilot records (E1), sentence = the CounterFact prompt, the answer read at the last position, in four groups: **candidates** (medium right, small wrong, 780), **both right** (1,372), **small right, medium wrong** (437), **both wrong** (19,200). Position 0 (the start token) is never changed.

**Primary arm R, replacement (the "stitched model").** At every position except the first, small's layer-8 state is replaced by T(h_M) = (h_M - mu_src) W + mu_dst, where h_M is medium's state on the same sentence; small's layers 8 to 11 and its output then run as normal. No dose, no filter, nothing to tune: R is run on all facts and nothing is chosen on the data.
**Secondary arms (they use a fixed split of the 780 candidates into 100 dev and 680 test, seed fixed, to choose k and alpha by dev mean log-rank gain; ties to the smaller).** F: add alpha * (T(h_M) - h_S) (alpha in {0.25, 0.5, 1, 2, 3}; alpha = 1 equals R). S: encode T(h_M) and h_S with small's layer-8 SAE (`gpt2-small-res-jb`), keep at every position the k features (k in {5, 20, 100}) with the largest |difference| and add alpha times their decoded difference (the original SAE-filter idea).
**Controls for R (the answer is never used).** C1 wrong-sentence donor: medium's translated state from another sentence of the same token length (fixed seed) written into this one; C2 floor: the translated average medium state (the information destroyed); C3 random map: a random matrix of the same scale instead of the translator. Reported for the secondary arms only: C4 word push (the true answer's output direction in small at the last position, norm-matched; it uses the answer and is not required to be beaten).

**Measures.** (1) Rescue: the true answer becomes small's top-1 on the candidates. (2) Survival: the share still top-1 on the "both right" facts and on the "small right, medium wrong" facts (the second set is where medium's state can damage a correct answer). (3) Net effect: top-1 accuracy over all 21,789 facts for small (1,809, 8.30%), medium (2,152, 9.88%) and the stitched model. (4) Steering toward medium: the share of facts on which small's top-1 equals medium's top-1, right or wrong, for small alone and for the stitched model. (5) Rewordings: the rescue rate on the CounterFact paraphrase prompts of the candidates (the donor state is recomputed for each prompt). Descriptive breakdowns by the true answer (the ten most common cover 44% of the candidates), by small's starting rank and by medium's probability.

**Gate 8 (confirmed by the author), arm R, pair m2s_L16_L8, over the facts above:**
- (a) rescue at least **50%** of the 780 candidates;
- (b) net recovery: the stitched model's accuracy over all facts is at least **halfway** between small's and medium's (at least 9.09%);
- (c) rescue at least **10 points** above the strongest of C1, C2, C3, with a paired test on the candidates (McNemar) **p < 0.01**;
- (d) survival: at least **90%** of the "both right" facts stay right.
Reported, not gated: (4) agreement with medium's answers, the survival of the "small right, medium wrong" facts, rewordings, the secondary arms F and S (with C4), the breakdowns, and four other layer pairs (`m2s_L12_L8`, `m2s_L8_L6`, `m2s_L4_L2`, `m2s_L20_L10`) as an exploratory table that is not used to choose anything.
**Readings fixed in advance:** (a) to (d) hold = replacing small's state with medium's translated state carries medium's knowledge into small without telling it the answer; (a) fails but the agreement with medium's answers rises clearly (by at least 10 points) above small's own = small is steered toward medium's behaviour without the knowledge being carried (reported as that: an intervention on another model with no SAE on the donor, not a knowledge transfer); (a) and (b) fail but F or S do better = the full replacement carries too much noise and filtering helps; every arm fails and the agreement does not rise = Import with this map does not work. If the survival of the "small right, medium wrong" facts is low, small inherits medium's mistakes, and that is reported.

**Procedure.** New code only: `src/transfer/import_eval.py`, `tools/transfer/19_import_experiment.py` (with `--smoke`); no training; prompts of equal token length are batched; the tool prints progress, saves its log and a JSON (including the per-fact outcomes of R); a few minutes of GPU time. After the run: Entry 35 (a new journal entry), figures from the saved data, `PAPER_NOTES.md`, logs, push.
**Risks written down beforehand.** (1) The stitched model is limited by small's last four layers and by the translation error: on text it recovers about small's own quality, not medium's, so a partial result is the likely outcome. (2) Small may inherit medium's mistakes (survival of the 437). (3) The answers are skewed (French, Apple, English...): per-answer breakdown and the C controls. (4) The agreement measure also depends on small's baseline agreement with medium. (5) Each secondary arm uses 100 dev facts, a noisy guide to k and alpha.

*Result (recorded 2026-10-10):* Import by replacement (small's layer-8 state replaced by medium's layer-16 state translated by m2s_L16_L8; no training): rescues 262 of the 780 candidates (33.6%; controls: wrong-sentence state 0.8%, average state 0.0%, random translator 0.0%; paired p = 4e-73), but loses 298 of the 1,372 both-right facts (78.3% survive) and 304 of the 437 small-right-medium-wrong facts (30.4% survive); accuracy over all 21,789 facts falls from 8.30% (small) to 7.17% (medium alone: 9.88%); agreement with medium's answers 71.1% to 74.7%; no gain on rewordings (13.1% against 13.8%); the SAE-filtered difference rescues only 6.3%. Gate 8 FAILS: (a) 33.6% against 50%, (b) 7.2% against 9.1%, (d) 78.3% against 90%; (c) holds. Reading fixed in advance: (a) fails and the agreement with medium's answers rises by 3.6 points (under the 10 that counts as clear): Import with this map does not work as a way to improve small; note added after the result: the replacement does carry real, sentence-specific information (controls about 0). Data: `packs/cross_model_transfer/e2_import.json`; log `logs/e2_import.log`; Entry 35; Figure `e35_fig1_import`.

## Words used here
- **Residual stream:** the model's running internal state at each word position.
- **SAE feature:** one readable direction in that state, found by a sparse autoencoder.
- **Translator / map:** a table of numbers that converts one model's state into the other's coordinates.
- **Delta / change:** edited state minus unedited state, for the same text.
- **Stitching:** swapping a model's internal state for a translated one and seeing how well it still predicts words.
- **Rank-matched:** controls chosen to start at the same difficulty as the real targets.
