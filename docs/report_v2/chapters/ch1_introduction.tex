\chapter{Introduction}\label{ch:introduction}

\section{Background and Motivation}

Language models often finish a factual prompt with a generic word even though the right answer is only a few places down the ranking. Given ``The location of Massachusetts Institute of Technology is in'', GPT-2 Small \cite{r1} puts `` the'' first and `` Cambridge'' eighth. We call this \textbf{suppressed factual recall}. The name only describes the output ranking; it does not say what the model ``knows''. The usual fixes change the model itself. Fine-tuning and closed-form weight edits such as ROME \cite{r2} and MEMIT \cite{r3} are permanent, and when they are applied again and again they first wear away earlier edits and then break the model \cite{r4}. Retrieval and in-context editing \cite{r34,r31} leave the weights alone, but they hand the fact to the model as extra text.

Mechanistic interpretability gives a third option. A sparse autoencoder (SAE) \cite{r6,r7} rewrites a layer's activations in a much wider basis where only a few directions are active at a time. These directions, called \emph{features}, often line up with single concepts. A feature is a direction in the residual stream, so we can turn it down (\emph{mute}) or up (\emph{boost}) during one forward pass and throw the change away afterwards. If that works, a wrong answer can be repaired \textbf{transiently}, with no weight touched, and the repair can be read as a short list of named features. This project asks whether it works, how to build it, and what it actually does.

We want to be clear about how the pieces relate. The \textbf{main line} (stages 1 to 11) is the project itself: a transient SAE edit of GPT-2 Small, the question of how to choose that edit (a hand-built search, a trained network or gradient descent), and what the edit does apart from the one number it is tuned for. The \textbf{ROME reference} (stage 12) is a short outside check on our measurements (Chapter~\ref{ch:rome}). The \textbf{cross-model transfer study} (stage 13) is not a later version of the system. It is an \emph{applied side study}. Once the edit, the controls and the benchmark existed, we used them on a new problem to see whether the interpretability and intervention work was useful beyond the single model it was built for.

\section{Problem Statement and Research Questions}

\textit{Suppose GPT-2 Small ranks the true answer to a prompt below first. Can a transient edit of SAE features during one forward pass bring the answer to the top, how should that edit be chosen, and what does reaching the top tell us?} Five research questions follow from this.
\begin{enumerate}
  \item \textbf{RQ1 (what works).} Which way of choosing features and strengths brings a suppressed answer to rank 1, and which ideas fail?
  \item \textbf{RQ2 (limits).} What holds such an edit back: the depth of the intervention, the safety rule, or the supply of features it can use?
  \item \textbf{RQ3 (choosing the edit).} Can a program choose the edit better than a hand-built search, either a trained network or gradient descent on the edit itself?
  \item \textbf{RQ4 (meaning of success).} Does rank 1 show that a fact was recovered? What else does the edit change: reworded prompts, neighbouring facts, unrelated prompts, generated text?
  \item \textbf{RQ5 (application).} Can the change an edit makes in one model be carried into another model at inference time without changing weights, and what exactly is carried?
\end{enumerate}

\section{Objectives, Scope and Contributions}

We set out to build a transient edit that changes only the intended feature contribution, to record with numbers what each design decision bought and which ideas failed, to build a benchmark with held-out prompts and exact paired statistics, to measure side effects against controls, and to apply the tools to the transfer question with pass bars fixed before each run. We use GPT-2 Small with the SAE release \texttt{gpt2-small-res-jb} (24,576 features per layer), layer 8 in all later studies, single-token facts from ROME's \texttt{known\_1000} and CounterFact \cite{r2}, and next-token measurements. The side study adds GPT-2 Medium, which has no SAE. Other models, a head-to-head comparison with ROME, MEMIT or in-context editing (Section~\ref{sec:rome-open}), and a full evaluation of generated text are outside the scope.

The main contributions are the following. (1) A record of the trial and error from single-feature ablation to gradient descent (Chapter~\ref{ch:evolution}) \cite{p1,p13}. (2) A transient edit whose design choices are backed by measurements: delta patching, causal ranking, a strict per-feature safety filter, pool refill, and candidates from all prompt positions (10 of 13 prompts reach rank 1, against 4 with the last token only). A batched implementation cut model calls per prompt and layer from 186 to 6 with identical results \cite{p5,p7}. (3) An equal-budget comparison. On 300 held-out CounterFact prompts gradient descent reached rank 1 on 271, against 161 for a sweep given the same range and 94 for the original settings, with lower side effects on the same prompt and 5 to 6.5 times less compute \cite{p13}. (4) A control showing that rank 1 is a weak test: an additive edit pushes random words to rank 1 on 20 of 20 prompts. This led us to withdraw an early ``knowledge absent'' classification \cite{p14}. (5) An applied side study with fixed pass bars: a linear translator between GPT-2 Small and Medium, Export and Import tests with controls, a documented search that locates the limit, and a first positive Import result \cite{p16,p17}.
