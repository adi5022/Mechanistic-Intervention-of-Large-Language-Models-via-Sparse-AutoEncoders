\section{Software, Hardware and Application}

The system is written in Python with PyTorch \cite{r22}, TransformerLens 3.5.1 \cite{r13} (which gives every GPT-2 activation a named hook point and can run the model from a saved intermediate state), SAELens 6.45.3 \cite{r14} (which loads the \texttt{gpt2-small-res-jb} dictionaries \cite{r15}), Neuronpedia \cite{r20} for feature descriptions, and Streamlit for the application. The main-line studies ran on a GTX 1660 Ti PC (PyTorch 2.6.0, CUDA 12.4). Caching, the headroom study, the strength models and the transfer study ran on an RTX 4050 laptop (PyTorch 2.5.1, CUDA 12.1).

The application \texttt{experiment\_app.py} has seven tabs and three tiers: the interface, the intervention engine, and the model and data layer (cached GPT-2, SAEs, fact sets and per-prompt caches). The \emph{Hybrid mute and boost} tab carries both editors behind a choice of editing method. You can pick the fixed sweep, with its strengths, cumulative sweep, pool refill, safety filter and GPU-batched switch, or gradient descent, with its steps, learning rate, margin and weights. It also has a live tracker, a stopwatch and a session-history record. The \emph{Prototype lab} runs gradient descent with the optional additive edit, shows the baseline and edited text side by side, and applies the same edit to follow-up prompts. \emph{Batch} runs studies in background workers, \emph{Repair \& SAE limit} shows the diagnostics of Section~\ref{sec:repair}, \emph{Sequential vs Batched Proof} times the two code paths, \emph{Monosemanticity Analysis} inspects features, and \emph{Session history} stores every run. The edit itself lives in \texttt{src/hooks.py} (Equation~\ref{eq:delta}), \texttt{src/editing.py} (screening, causal ranking and the safety checks of Equation~\ref{eq:safe}), \texttt{src/hybrid\_runner.py} (the headless sweep, which reproduces the application exactly) and \texttt{src/gradient\_editing.py} (Equations~\ref{eq:a} to~\ref{eq:add}). The transfer study adds only new files (\texttt{src/transfer/}, and tools \texttt{00} to \texttt{27} in \texttt{tools/transfer/}). We import older functions and never edit them, so earlier results cannot change.

\section{Correctness Checks and Engineering Lessons}

We checked every fast path against a slower reference before using it, and we kept the checks as scripts. Batched ranking matched sequential ranking (identical feature lists, probabilities to $10^{-9}$, and 60 of 60 safety decisions). The cached-state path matched the full model (identical logits on one machine, within $10^{-5}$ on the other). A random per-feature edit through the cache path gave the same target rank as the real hook, and the gradient-descent tuning path agreed with the real hook in every recorded run. Built-in sanity checks stop a run if something does not match, and one of them caught an error in the cache builder (it passed a multiplier of 1.0 where 0.0 was meant) before any data was written. Three problems could have ruined results without raising any error.
\begin{itemize}
  \item \textbf{A thread race removed the start-of-text token.} In TransformerLens, tokenising with the start token switched off temporarily changes a setting shared by the whole model. When two Streamlit sessions overlapped, the wrong value could be written back for good, and every later prompt was tokenised without its start token (rank 28 instead of 22 on one prompt). Of 57 recorded application runs, 16 had wrong baselines, all from one server process, and none of them is used in a table. The fix tokenises directly and never touches the model's configuration.
  \item \textbf{A timer measured the network} (46 s against about 10 s of model time), and \textbf{chained hooks disagreed with the combined check} (rank 66 against 59). We moved the look-ups out of the timed region and now use one combined hook.
  \item \textbf{GPU memory.} A padded training set of 7,550 texts (3.8 GB) nearly filled the 6 GB card and made runs five to ten times slower with no error at all (6.2 hours instead of one). Training tensors now stay on the CPU.
\end{itemize}

\section{Reproducibility and Development Process}

Every tool prints its pass rule, saves its raw output as a log, and writes a result file with the per-run details. The logs and results of every experiment are copied into a data pack under version control, and the figures in this report are drawn from that pack by scripts that run no model. We optimised in one bounded step at a time: find one bottleneck, measure the reference, make one change, check equivalence on a fixed case, log it, and only then approve the next step.

The software and this report were developed with AI coding assistants (Antigravity AI earlier, Claude later) under the authors' direction. The authors chose the questions, pass bars, controls and each next experiment, and ran or approved every long job.
