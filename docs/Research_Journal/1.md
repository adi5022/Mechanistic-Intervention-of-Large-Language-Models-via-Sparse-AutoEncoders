# FeatureScalpel — Project Progress & Roadmap

**Last updated:** July 2026
**Status:** MVP prototype working; core reliability testing not yet started.

---

## 1. What this project is

FeatureScalpel is a **transient activation steering mechanism** for GPT-2-small. It corrects
factual errors *at inference time*, without touching the model's weights.

**Core claim:** when a language model produces a wrong answer, sometimes the *correct* answer
is still present inside the model's internal representation — just outranked by a wrong one.
This project finds the specific internal signal responsible for suppressing the correct answer,
and turns it down for that one forward pass only. Nothing about the model changes afterward.

**Explicit scope boundary (important):** this method only works when knowledge is
*suppressed* (present but outranked). It does **not** work when knowledge is *absent*
(never encoded in the model at all). This isn't a flaw — it's a measured precondition,
and it mirrors standard practice in the literature (see §4).

**How this differs from related approaches:**
- **ROME / MEMIT** (weight-editing): permanently rewrite model weights to store a new fact.
  Effective but risky under repeated edits — errors compound ("catastrophic degradation
  under sequential edits"). This project never touches weights, so this failure mode
  doesn't apply — trading permanence for safety.
- **RAG**: injects external information into the context. This project does not add any
  external information — it only rebalances signal that's already inside the model.
- **Blunt activation steering / mean-difference steering / Activation Addition /
  Representation Engineering**: typically adds a fixed vector to raw (superposed) activations
  to shift broad behavior. This project instead intervenes on individual, disentangled
  **SAE features** (see §2), and uses **partial**, tuned suppression rather than a blunt
  on/off toggle — this is the mechanism expected to give better specificity (fixing the
  target fact without collateral damage to unrelated facts).

## 2. Conceptual foundation (why SAEs, in plain terms)

- **Toy Models of Superposition** (Anthropic): neural nets have more concepts to represent
  than they have neurons, so they blend multiple unrelated concepts into the same neurons
  ("superposition"). Raw neurons are rarely clean/interpretable.
- **Towards Monosemanticity** / **Cunningham et al. SAE paper**: trains a much wider,
  sparse network (a Sparse Autoencoder, SAE) that re-expresses a model's blended activations
  in a larger space where individual directions ("features") tend to correspond to single,
  nameable concepts.
- This project uses a **pretrained SAE** (`gpt2-small-res-jb`, SAELens) on GPT-2-small's
  layer-8 residual stream (`blocks.8.hook_resid_pre`). This is what makes it possible to
  turn down *one specific concept* without disturbing everything else at once.

### Correction re: AxBench (verified via search, not memory)
Earlier framing said "AxBench doesn't use SAEs, we do" — **this is wrong and should not
appear in any writeup.** AxBench (Wu et al. 2025) explicitly benchmarks SAE-based steering
alongside DiffMean, prompting, finetuning, and their own ReFT-r1 method, on Gemma-2 models.
Their finding: prompting outperforms all tested methods for steering, and SAEs specifically
are not competitive on steering or concept detection in their benchmark. A 2026 rebuttal
paper argues SAEs can perform close to on par with LoRA when features are selected/labelled
better — so this is a **live, contested comparison**, not settled.

**Correct framing of this project's novelty relative to AxBench:** AxBench tests raw
SAE-feature steering for broad concept steering (e.g. "talk more about X") on larger,
instruction-tuned models. This project tests a narrower, different claim: whether a
**causally-selected** (not just highly-activated), **partially-ablated** SAE feature can
perform targeted **factual correction** on a smaller base model. Different task, different
model, different intervention style — state it as a distinct comparison, not as "AxBench
skipped SAEs entirely."

## 3. Architecture (as currently built)

- `sae_utils.py` — loads GPT-2-small (TransformerLens `HookedTransformer`) and the
  pretrained SAE at `blocks.8.hook_resid_pre`.
- `hooks.py` — `make_ablation_hook(feature_id, sae, strength)`: encodes the residual
  stream into SAE feature space, scales one feature by `(1 - strength)`, decodes back,
  and applies only the *delta* (avoids injecting SAE reconstruction error).
- `editing.py` — `run_causal_selector`: finds the top active SAE features on a prompt's
  final token, fully ablates each one (one at a time), measures the resulting change in
  target-token probability (causal delta) and ranks features by that — **not** by raw
  activation magnitude.
- `evaluation.py` — now contains `classify_fact` and `scan_fact_batch`: classifies any
  (prompt, target) pair as `already_correct`, `suppressed`, or `absent` based on the
  model's clean (unablated) baseline behavior, using rank and probability thresholds.
- `app.py` (Streamlit) — three working sections:
  - **Section 0** (new): real-time eligibility check on the prompt/target the user types
    (green/blue/red), using `classify_fact`.
  - **Section 1**: automated causal feature selector with ranked results table.
  - **Section 2**: live ablation-strength slider with before/after top-5 token comparison.
  - Section 3 (specificity check) — **not yet built**.

## 4. Genuine findings so far

1. **Raw SAE activation magnitude ≠ causal importance.** Demonstrated empirically —
   the highest-activating feature is not always the one that actually flips the answer.
2. **Full ablation causes specificity leakage**; partial ablation at a tuned strength
   (~0.2–0.3) can correct a target fact without the same collateral damage — validated
   on exactly **one** example (Eiffel Tower → Paris) so far. Not yet a general claim.
3. **Automated causal selector validated**: feature `11149` was independently
   (re)discovered as the top-ranked causally important feature for the Eiffel Tower
   prompt, with no manual feature-hunting required — confirms the selector mechanism
   works, at least for this case.
4. **Applicability boundary measured, not guessed.** Ran the classifier over 46 real
   fact pairs sourced from ROME's own `known_1000.json` dataset (not fabricated):
   - 15 → already correct at baseline (nothing to fix)
   - 8 → knowledge absent (unfixable, correctly excluded)
   - 22 → confirmed **suppressed** (valid intervention candidates)

   This directly parallels methodology in the **ROME paper** (Meng et al., 2022), which
   also pre-filters its evaluation facts to ones the base model already predicts with
   reasonable confidence, before testing edits. This project rediscovered that same
   necessity independently — cite ROME's own methodology as precedent, since it is one.

5. **Prompt phrasing matters more than expected.** GPT-2-small is not instruction-tuned;
   naive question-style prompts (e.g. "The capital of India is") often just continue
   grammatically ("the") rather than answering factually. Only carefully-templated,
   cloze-style prompts (as ROME's authors hand-tuned) reliably elicit factual completion.
   This is a **prompt-format problem**, separate from the suppressed/absent distinction,
   and the eligibility scanner should ideally catch this class of failure too.

6. **Possible feature entanglement across token variants**, observed but not yet
   confirmed: in some cases, ablating a feature shifts probability mass to a *different
   token variant of the same wrong answer* (e.g. a different tokenization of "London")
   rather than to the correct target. Suggests some top-ranked features may encode a
   general "wrong answer" direction rather than one clean, isolated concept — worth
   testing directly (see §5, Step 1).

## 5. Immediate next step (in progress / agreed)

**Step 1 — Iterative ablation + specificity check (the actual current priority).**

- Instead of ablating only the single top-ranked feature once, iteratively:
  1. Run the causal selector.
  2. Ablate the top feature.
  3. Re-run the causal selector on the now-modified activations to see if a *new*
     feature has become the dominant blocker.
  4. Repeat until the target token becomes the model's top-1 prediction, or a round
     limit is hit.
  5. Record **how many features it took** for each fact — this becomes a real,
     reportable per-fact metric.
- Then, **specificity check**: take the exact set of features ablated to fix Fact A,
  and re-test them against a batch of *unrelated* control prompts, to confirm they
  didn't break something else. (This is Section 3 from the original project plan —
  not a new idea, just now precisely specified.)
- This must be validated across the 22 confirmed-suppressed facts before any claim
  about "the technique works" can be made general. Currently validated on **n = 1**
  (Eiffel Tower only).

This is a hard prerequisite for everything in §6 — a learned predictor or a faster
search method is only as good as the search process generating its training signal.

## 6. Future plans (not started — in priority order)

1. **Iterative ablation + specificity check** (§5 — immediate priority, in progress).
2. **Attribution Patching** — a faster approximation to causal feature ranking.
   Instead of ablating each candidate feature and rerunning the full model (current
   brute-force approach: N reruns for N candidate features), Attribution Patching
   estimates each feature's causal effect using a single gradient pass. Originated
   as an informal technique by Neel Nanda (2023); formalized and stress-tested in
   **"AtP\*: An Efficient and Scalable Method for Localizing LLM Behaviour to
   Components"** (Kramár et al., DeepMind, 2024) — read this paper, not just the
   original informal writeup, since it covers where the plain gradient approximation
   breaks and how they fixed it. Only needed once brute-force search becomes too slow
   (e.g. scaling past the current 22-fact set to hundreds/thousands).
3. **ROME baseline** and **mean-difference steering baseline** — currently zero code
   for either. This comparison is the central evidence for the project's core novelty
   claim and does not yet exist.
4. **Aggregate benchmarking logic in `evaluation.py`** — batch-running the (by-then
   iterative) ablation pipeline across all 22 suppressed facts and reporting success
   rate, best strength range, etc.
5. **Model upgrade consideration — Gemma Scope.** GPT-2-small's weak, non-instruction-
   tuned factual recall limits which prompts work at all. Google DeepMind's
   **Gemma Scope** provides pretrained SAEs for Gemma-2-2B/9B across multiple layers,
   removing the need to train a new SAE from scratch. A candidate upgrade path, but
   deliberately **sequenced after** the current pipeline is proven reliable — switching
   base models too early would restart validation from zero.
6. **Learned feature-ablation predictor (originally "idea 4c").** Train a small neural
   network to predict which SAE feature(s) to ablate for a given fact, using the
   (by-then-validated) iterative search process as a label generator — a distillation
   approach (same family of idea as AlphaZero's policy network learning to approximate
   expensive tree search). Not data fabrication, but not metric-independent either:
   labels are only as good as the causal-delta metric and stopping rule used to generate
   them, and this must be stated as a limitation.

   **Related, already-published prior work to cite (so this isn't claimed as
   untouched territory):** Automated Circuit Discovery (**ACDC**, Conmy et al., 2023)
   and **Edge Attribution Patching** (Syed et al., 2023) already automate causal-component
   discovery, at the attention-head/MLP level rather than SAE-feature level, and without
   a learned distilled predictor stage. This project's likely genuine gap: doing this at
   **SAE-feature granularity**, plus a **learned amortized predictor** as an end product —
   state it as that specific combination, not as an unprecedented idea.

   **Scale requirement to flag now:** 22 facts is far too small a set to train a
   generalizing network on — expect to need the fact set expanded by 1–2 orders of
   magnitude (hundreds to low thousands), pulled from the fuller ROME/CounterFact
   datasets, once the underlying search process is trustworthy.

   **This is explicitly next-semester scope**, not something to fold into this
   semester's three review milestones alongside everything else still outstanding.

## 8. Honest current-state summary (one paragraph)

A working, automated (non-hardcoded) causal feature selector exists, along with a
measured applicability boundary (22 of 46 real fact pairs are valid test cases) and a
live eligibility guard in the app. What does **not** yet exist: proof the intervention
generalizes beyond one example, a specificity check, any baseline comparison (ROME,
mean-difference steering), or aggregate benchmarking. The immediate next step is
building and validating the iterative ablation + specificity-check pipeline across
the 22 confirmed-suppressed facts — everything else (attribution patching, model
upgrades, the learned predictor) is deliberately sequenced after that.
