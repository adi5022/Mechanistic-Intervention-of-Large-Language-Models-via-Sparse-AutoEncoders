## 1. Why
A multiplier cannot switch on a feature that is silent (0 x m = 0), and the 29 prompts gradient descent failed on in Entry 29 (and the names / "Adi" / "rapist" hand trials of Entry 28) are mostly deep targets, where the features that would help may be silent. The additive knob lets the edit add volume to silent features: `new volume = old volume x multiplier + added amount`.

## 2. Method (src/gradient_editing.py, `run_gradient_descent_edit(..., additive=True)`; all new options default OFF)
- **Which features may be added:** features whose activation is exactly 0 at the last position (so a feature is never both multiplied and added to at that position). Among them, the top `M` (default 200) by a first-order score: one backward pass of the target margin with respect to the layer-8 residual at the last position gives a vector r; `W_dec @ r` scores all 24,576 features; only positive scores qualify (`silent_candidates`).
- **Amount:** `c_k = cap * (sigmoid(s_k) - sigmoid(s0))` for `s_k >= s0` (else 0), `s0 = -6`, so every amount starts at exactly 0 and is non-negative. `cap = cap_factor x` the loudest activation on the real prompt positions (the start-of-text token is excluded as a precaution because its activations can be very large; on the default prompt the cap was 48.5 both before and after this change, so it made no difference there). Added at the LAST position only, as `c @ W_dec[k]`.
- **Extra loss:** `lam_add * sum_k c_k / cap` (default 0.005); the additive parameters have their own optimiser group (learning rate 0.3).
- **Option `kl_always`:** charges the KL term on every step, not only once the target leads (the failing-prompt flaw documented in Entry 28 section 8). Default OFF.
- **Real-hook check:** the final edit is applied through the full model with `make_scale_and_add_hook` (`src/hooks.py`: the sweep's scale-map delta patch plus the added vector at the last position); the reported rank, probability, KL and top-1 come from that pass.
- **Returned:** `added {feature id: amount}`, `add_cap`, `add_summary` (how many additions are at least 1% / 10% of the cap, total in caps, largest), `edit_size_frac_norm` (norm of the whole change at the last position / norm of the residual there).

## 3. Self-checks (`tools/check_additive.py`; all pass)
1. **Regression:** with the options off, 6 prompts reproduce the Entry 29 `gd` ranks and KL (largest KL difference 1.3e-06).
2. **No-edit start:** with the additive edit on and 0 steps, the rank is unchanged and KL is about 1e-7 (amounts exactly 0).
3. **Path equality:** a random multiplier plus additive edit through the delta shortcut equals the same edit through the real hook (largest logit difference 7.6e-06).
4. **Silent only:** no added feature has activation above 0 at the last position, amounts stay within [0, cap], and the tuning-path rank equals the real-hook rank.
Two bugs were caught on the way and fixed: (a) a tiny non-zero start (sigmoid(-8) = 3.4e-4 per feature) was NOT harmless: the candidates are chosen because they help, so 200 of them add coherently (rank 5 became 4 at step 0, a failure of check 2); (b) clamping at the exact start killed the gradient (the first hand trials showed no additions at all); the final form above keeps the gradient at the start.

Caveats that matter for reading this table:
- **The targets are single token pieces.** "Aryan", "Rajesh" and "Adi" are multi-token words and only their last piece is scored (the new top-1 words are "ryan", "esh", "i"); " Hong" is only the first piece of "Hong Kong". Rank 1 here is rank 1 for a piece, not for the word.
- **The additive edits are large.** The change is 55% to 161% of the residual norm at the last position (Entry 24 measured free residual pushes at 5% of the norm). This matters for any use that keeps the edit on while generating text.

## 7. Protocol for the controlled tests (fixed before running)
1. **Tune on the validation split only (150 prompts):** M fixed at 200; cap factor in {0.25, 1.0} and sparsity weight in {0.005, 0.02} (four additive arms plus `gd`), on both the true-answer targets and the counterfactual targets of the validation split. Selection rule, fixed in advance: the setting with the largest total of prompts reaching rank 1 over the two validation sets; ties broken by the lower median edit size, then the lower median KL.
2. **Freeze the chosen setting and run the 300 test prompts once,** arms `gd`, `gd_klall`, `gd_add` (frozen setting), `gd_add_klall`, reusing the sweep and `gd` results of Entry 29 for the same prompts (`--baseline-from`).
3. **Run the counterfactual-target set** (test split, `--targets new`) with `gd` and `gd_add`.
4. Report: rank 1 (exact McNemar, `gd_add` vs `gd`), the prompts rescued, same-prompt KL on shared successes, number and size of additions, edit size, collateral on unrelated prompts, time; per band. Add figures to `tools/make_journal_figures.py`.

## 8. Limitations to carry into the results
- An additive edit is a strictly stronger edit than multipliers alone, so more prompts reaching rank 1 is expected; the informative quantities are the edit size, the side effects, and whether the switched-on features are meaningful (inspect them in the tab).
- Adding volume to features that point at the target is closer to writing the answer in than to recovering suppressed knowledge; it must not be described as "the model knew it".
- The addition is at the last position only. It is not carried through generated text.
- First-order selection of the silent candidates can miss useful features; M = 200 is a choice.

## 10. Control (added later the same day): the additive edit can push random words to rank 1
Prompted by the author noticing that every prompt tried in the new tab reached the target, very fast, even for an arbitrary name ("Dutch disease, which is called after" to "Kevin": start rank 1036, rank 32 after 7 steps, rank 1 by about step 10, edit size 83% of the residual norm).
**Test** (`tools/control_random_targets.py`, data in `packs/additive_control/results.json`): 20 validation prompts (seed 11), each paired with a random, unrelated single-token word drawn from the whole vocabulary (start ranks about 270 to 44,600, most above 10,000). 100 steps, Top N 200.
| Arm | Reached rank 1 | Median end rank | Median KL | Median edit size (share of residual norm) |
|---|---|---|---|---|
| Multipliers only | 1 / 20 | 1245 | 1.87 | 39% |
| + additive, cap factor 1.0 | **20 / 20** | 1 | 0.76 | **192%** |
| + additive, cap factor 0.25 | **20 / 20** | 1 | 0.91 | **126%** |
**Reading.** The additive edit is strong enough to force almost any word to rank 1, at an edit larger than the residual signal itself (individual edits up to 387% of the norm in the first run). Reaching rank 1 with it is therefore NOT evidence that anything the model knows was recovered; it is the analogue of fitting random labels in deep learning. Reducing the cap factor from 1.0 to 0.25 did not change this.
**Consequences.**
1. The success rate is not a meaningful test for the additive arm. Section 7's selection rule (largest number of rank-1 prompts on validation) is SUPERSEDED: it would reward the strongest, least meaningful edit.
2. A meaningful test needs (a) selectivity: settings where true answers still succeed but random words fail (smaller caps than 0.25 have not been tried), and (b) generalisation: the edit tuned on a prompt must still help on reworded versions of the same fact and leave neighbouring facts alone (CounterFact paraphrase and neighbourhood prompts). Neither has been run. The protocol is to be re-agreed with the author before any further additive run.
3. The Prototype lab tab now has the additive checkbox OFF by default and shows a warning with the edit size and this control.
4. The multiplier-only method, in the same control, reached rank 1 on 1 of 20 random words (median edit 39% of the norm), so it is far more constrained; Entry 29's results for it are not affected by this.
The 6 hand trials of section 6 were all won with the strong edit and should be read in this light.

## 11. Reworded-prompt test (tool: `tools/test_generalisation.py`; data: `packs/generalisation/true40/`, `packs/generalisation/random40/`)
**Question.** Does an edit tuned on ONE prompt carry over to the same fact worded differently, and does it leave nearby facts alone? **Design.** 40 held-out test prompts (10 per starting-rank band 2-5 / 6-20 / 21-100 / 101-1000, seed 7, true answers). The edit is tuned on the ORIGINAL prompt only (100 steps, Top N 200, all positions). That exact edit (the same per-feature multipliers and, for additive arms, the same added amounts) is applied unchanged, through the real hook and by feature id, to (a) the fact's CounterFact `paraphrase_prompts` (80 reworded prompts in total, 2 per fact), (b) up to 10 `neighborhood_prompts` per fact (other subjects with the same relation), (c) the 20 neutral prompts of the runner. Arms: `gd` (multipliers only), `gd_add@cap=1.0`, `gd_add@cap=0.25` (additive, M 200, sparsity weight 0.005). **Control.** The same 40 prompts with a RANDOM unrelated single-token word as the target (seed 8), so that "carries over" can be compared with a target that has nothing to do with the fact. The original prompt's rank through the hook equalled the tuning-pass rank on every prompt (0 mismatches).

**Results, true answers (40 prompts)**

|---|---|---|---|
| Original prompt at rank 1 | 36 / 40 | 40 / 40 | 40 / 40 |
| Median edit size (share of residual norm) | 21% | 29% | 23% |
| Reworded prompts where the target's rank improved | 79% | 88% | 86% |
| Reworded prompts that reached rank 1 | 9% | 16% | 15% |
| Median target rank on reworded prompts (unedited 94) | 36 | 4 | 12 |

| Nearby facts: mean KL / top word changed / target became top word | 0.111 / 20% / 18% | 0.196 / 32% / 31% | 0.136 / 26% / 25% |

**Results, control: random unrelated words (the same 40 prompts)**
| | gd | gd_add cap 1.0 | gd_add cap 0.25 |
|---|---|---|---|
| Original prompt at rank 1 | 1 / 40 | 40 / 40 | 39 / 40 |
| Median edit size | 40% | 177% | 119% |
| Reworded prompts where the target's rank improved | 96% | 100% | 100% |
| Reworded prompts that reached rank 1 | **0%** | **25%** | **16%** |
| Median target rank on reworded prompts (unedited 17,504) | 11,832 | **4** | **9** |
| Mean log10 gain in rank | 0.19 | 3.51 | 3.09 |
| Nearby facts: mean KL / top word changed / target became top word | 0.444 / 24% / 0% | 1.680 / 72% / 27% | 1.336 / 65% / 19% |
| 20 neutral prompts: mean KL / top word changed | 0.016 / 10% | 2.273 / 82% | 1.518 / 74% |

**Reading.**
1. **The additive edit "carries over" to reworded prompts equally well for a random word (median rank 4 / 9, 25% / 16% at rank 1) as for the true answer (4 / 12, 16% / 15%).** The transfer therefore carries no information about the fact: it is a prompt-independent push toward the target word. The same push moves the top word on 82% of unrelated prompts (KL 2.27) for random targets. The additive edit does not pass the test: it transfers to everything.
2. **The multiplier edit behaves differently for true and random words**: true answers end at median rank 36 on reworded prompts (from 94) and reach rank 1 on 9% of them; random words end at 11,832 (from 17,504) and reach rank 1 on 0%. This is consistent with a modest fact-related component in the multiplier edit. It is NOT a clean test: the two sets start at very different ranks (94 vs 17,504), and "improved" counts any improvement however small (96% for random words with a median log10 gain of only 0.19), so the rank-1 share and the log10 gain are the more informative columns, and the log10 gains are not far apart (0.30 vs 0.19).
3. Even for true answers the multiplier edit makes the target rank 1 on only about 1 in 10 reworded prompts, so a single-prompt edit is mostly local.

**Limitations.** 40 prompts, one seed; 80 reworded prompts (CounterFact paraphrases are sometimes odd, with unrelated text before the subject); the "nearby facts: target became top word" column includes legitimately shared answers; the random-word control is not matched on start rank. A rank-matched control (random words whose start rank on the original prompt is similar to the true answer's) is the clean follow-up and has not been run. Other sweep settings and the sweep itself were not included (their final edits are not stored in the Entry 29 pack).

**Decision implied.** The additive edit should not be presented as a fix: rank 1, and now also transfer to reworded prompts, are both obtainable with a meaningless target. The multiplier edit remains the method with a modest, fact-related effect that carries partly to rewordings; the next test for it is the rank-matched control.

## 12. Correction to an earlier conclusion: "could not be steered" does not mean "not in the model"
**What was concluded earlier.** Journal 1 classified 46 ROME facts into already correct (15), suppressed (22) and "knowledge absent (unfixable, correctly excluded)" (8). Later entries repeat the reading for deep prompts ("almost unfixable": Entries 22, 23, 26 and the session report), and the ROME paper pre-filters its facts in a similar way. The implicit rule: if steering cannot bring a target near the top, the model does not represent it.
**Why that rule does not hold.** "Could not be reached" was a statement about the tool, not about the model. Multipliers can only rescale features that are already active (the Entry 22/23 notes on the active-feature ceiling and the untouched reconstruction error said as much). The additive edit (section 2) has no such limit: in the control of section 10 it brought random, unrelated words (" wagon", " pious", " envelope", start ranks 10,000 to 44,000) to rank 1 on 20 of 20 prompts. So (a) failure to steer with a weak tool is not evidence that the model lacks the fact, and (b) success in steering with a strong tool is not evidence that it has it. Reachability by steering cannot be used as the test for "the model holds this fact" in either direction. The 8 "knowledge absent" facts of Journal 1 are therefore not shown to be absent; the exclusion is withdrawn as a statement about the model (it remains a valid choice of evaluation set, as in ROME).
**What the additive edit is, in relation to feature injection.** It uses the injection mechanism (adding SAE decoder directions to the layer-8 residual stream) but only in a narrow form: the content is selected by the gradient of the TARGET TOKEN's margin, so it writes the answer's output direction, not a representation of a fact (subject and relation); it is applied at the last position of layer 8 where only blocks 8 to 11 remain; and its amounts do not depend on the prompt, which is why a random word transfers to reworded prompts as well as a true answer (section 11). It injects an answer, not knowledge. Injection of a representation of a fact (for example the difference between the layer-8 state of "The capital of France is Hong Kong. The capital of France is" and of the clean prompt, added to the clean run) and the steering-controller front end are NOT implemented.
**A possible replacement measure, not yet run.** A graded measure instead of reachability: the size of the smallest additive edit (as a share of the residual norm) that brings the target to rank 1, on the original prompt and on reworded prompts. Caveat recorded here because it was first misread: in the section 11 runs the true answers needed a smaller edit (median 29% of the norm, additive cap 1.0) than random words (177%), but that comparison is largely circular: the true answers started at median rank 94 and the random words at 17,504, and the size of the push needed follows the gap between the target's score and the top word's score, which the starting rank already shows. Those edits were also not tuned to be minimal, so the sizes are loose upper bounds. The measure only carries information beyond the starting rank if it is compared with RANK-MATCHED controls (random or unrelated words that start at a similar rank to the true answer) and if the minimal edit is actually searched for (for example the smallest scale factor of the tuned edit that still reaches rank 1).
