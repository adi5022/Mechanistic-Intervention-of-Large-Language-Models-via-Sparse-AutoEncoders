# Research Journal Entry 28: Gradient-descent per-feature editing in the Hybrid tab (a choice next to the fixed mute / boost sweep)

**Date:** October 3, 2026
**Branch:** `gradient-descent-editing` (branched from `4618a30` of `pool-refill-implementation`; code commit `af485bb`)
**Status:** Built, checked, and tried by hand on about 12 distinct prompts. NOT yet tested at scale: no held-out set run, no equal-budget comparison with the sweep, no side-effect measurement for the sweep, no generation test. Every number below is from single hand-picked prompts and is exploratory, not a result.
**Comes from:** Entry 27 (the "free per-feature optimum" in the one-shot proxy reached about 73% of held-out prompts, far above everything learned). **Future idea built on it:** `docs/future_scope.md`.

## 1. What this is, in one paragraph
A new choice at the top of the Hybrid tab ("Editing method"). The default is the existing fixed mute / boost sweep, unchanged. The new option, "Gradient descent (one multiplier per feature)", gives every candidate feature its own multiplier and tunes all of them together on the given prompt by gradient descent, starting from no edit. It replaces the mute / boost strengths, batch sizes, cumulative sweep, pool refill and safety filter controls. This is the same procedure as the "oracle" in `src/feature_models.py` (Entry 27), applied live to one prompt on the real model.

## 2. Exact method (so it can be reproduced and criticised)
Code: `src/gradient_editing.py` (`run_gradient_descent_edit`); UI and results display: `experiment_app.py`, Hybrid tab.

- **Candidates:** the Top N features by maximum activation over the prompt positions (BOS excluded) for "All prompt positions", or the features active on the last token for "Last token only". The number actually used is min(Top N, number of active features), e.g. 92 for "The sky is", 156 to 200 for the other prompts tried.
- **Parameterisation:** each candidate k has a free number z_k. Its multiplier is `1 + a_k` with `a_k = -1 + 3 * sigmoid(z_k)`, so the multiplier lies between 0 (feature removed) and 3 (tripled). z starts at the value that gives `a_k = 0` for every feature (no edit).
- **The edit:** `delta = sum_k a_k * act_k(p) * decoder_k`, added to the saved layer-8 residual state at EVERY prompt position p (act_k(p) is feature k's activation at position p in the clean run). Blocks 8 to 11 are then run from that state; the final norm and unembedding are applied to the last position only. Because the SAE decode is linear, this equals the delta-patch hook used by the sweep (`x' = x + decode(edited) - decode(original)`); reconstruction error is untouched, as everywhere in this project.
- **Loss (the same form as Entry 27):** `relu(margin - (target logit - strongest other logit)) + lam_kl * KL * [margin reached] + lam_size * sum_k |a_k| w_k`, where `w_k` is feature k's share of the total maximum activation. KL is `KL(clean || edited)` over all tokens except the target and the clean top-1 (the "blocker"), renormalised, at the last position.
- **Optimiser:** Adam on z, learning rate 0.1, N gradient steps (N + 1 evaluations; step 0 is the unedited model). Gradients are taken with respect to z only (`torch.autograd.grad`); GPT-2's weights are not touched.
- **Which iterate is kept:** the one with the lowest key, where key = (1,000,000 if the target is not rank 1, else 0) + loss. So a successful iterate with the lowest loss is kept; if no iterate reaches rank 1, the one with the lowest loss is kept (which is NOT necessarily the one with the lowest rank).
- **Final check through the real hook:** the chosen multipliers are applied with the sweep's own scale-map hook (`make_scale_map_hook`) in a full forward pass of GPT-2, and the rank, probability, top-1 and KL shown in the app come from that pass. The tuning-pass rank is compared with it and the app warns if they differ.

## 3. Settings in the tab (defaults) and what each does
| Setting | Default | Effect |
|---|---|---|
| Top N Candidate Features, Candidate source | 30 (the study used 200) / All prompt positions | Which features may be edited (shared with the sweep). At 30 hard prompts can stop short (the Australia check ended at #5 at 30 and reached #1 at 200); use 200 for a fair test. |
| Steps | 100 | Number of gradient steps. More steps help only if the curve is still falling; about 6 s per 100 steps on the GTX 1660 Ti. |
| Learning rate | 0.1 | Size of each step. Too small crawls, too large bounces. |
| Rank-1 margin (logits) | 0.3 | The target must beat the strongest other token by this much in the loss. |
| Side-effect weight (KL) | 3.0 | Penalty on changes to the other tokens, applied once the target leads. Higher: fewer side effects, fewer successes. |
| Edit-size weight | 0.005 | Penalty on the total multiplier change, weighted by activation. Mild effect. |
Settings used here are the same numbers `tools/train_feature_net.py` uses for its oracle (steps 100, learning rate 0.1, lam_kl 3, size 0.005, margin 0.3).

## 4. How it differs from the fixed sweep
| | Fixed mute / boost sweep | Gradient descent |
|---|---|---|
| What it decides | which features and how many | how much, per feature |
| Strength | one mute strength for the muted pool, one boost strength for the boosted pool | its own multiplier for every candidate |
| Search | features added one step at a time (rank checked each step), safety filter, pool refill | about 100 gradient steps on all candidates at once |
| Reach per feature | `1 - mute` to `1 + boost` (e.g. 0.4 to 1.8 at 0.6 / 0.8) | 0 to 3 |
| Safety filter | each feature tested alone | none (the loss pushes harmful features back toward 1) |
| Passes | many forward passes, re-ranking and filtering each round | 101 forward + 100 backward, blocks 8 to 11 only, plus one full-model check |
| Side-effect number in the app | none | KL (nats) |

## 7. Observations (descriptive only; nothing here is a test)
1. On the six prompts where both methods were run, gradient descent ended nearer rank 1 every time (it reached rank 1 on three; the sweep on none of the six; the sweep did reach rank 1 on the easy "falling" prompt, where gradient descent was not run).
2. The side effect (KL) of gradient descent grew with the difficulty of the prompt: about 0.01 or less on the easy prompts, 0.25 to 0.9 on the middle and the failing prompts, 1.2 to 1.9 on the two rank-400-to-550 prompts that it won.
3. Prompts whose target is not a real or plausible answer (a random name, "Adi", "rapist" after "My nephew is a") did not reach rank 1 under either method. "Adi" is two GPT-2 tokens and the app scores only the last piece ("i"), which the app warns about.
4. Changing the learning rate, steps and side-effect weight moved the "powder" result only a little (#179, #164, #157), so the result did not depend sharply on those settings in that one case.
5. At the far tail the rank is a poor guide to closeness: on "Adi" the probability grew about 260-fold while the rank moved from #14149 to #4897.
6. On the Kaka prompt the two strongest boosts were Neuronpedia's "Kam" and "Kat" name features (spelling features, not sports). Whether the edit works through the name's token shape rather than through knowledge about the player is not known.
7. Timing, one machine, model compute only: gradient descent 5.9 to 7.0 s per 100 to 110 steps on every prompt (the very first run, 12.3 s, includes warm-up); the sweep 4.5 s when it succeeded in a few steps and 21 to 24 s on the hard "powder" prompt.

## 8. Limitations and open confounds (read before quoting any number)
- **Unequal edit budget.** Gradient descent may scale a feature anywhere from 0 to 3. The sweep at the strengths used reached only 0.4 to 1.8 (0.6 / 0.8), 0.5 to 1.7 (0.5 / 0.7), 0.7 to 1.5 (0.3 / 0.5). Part or all of the gap may be this. The test that separates it (the sweep at mute 1.0 / boost 2.0 on the same prompts) has NOT been run.
- **No safety filter and many features at once.** Gradient descent changed 154 to 199 of the candidates on most prompts (a change counted when the multiplier moves more than 0.05 from 1). Most multipliers sat near the ends of the range (on the "nephew" run: 86 of 156 below 0.15, 32 above 2.7).
- **Side effects are measured for gradient descent only,** and only as KL at the last position of the same prompt. Nothing has been measured on other prompts (neighbours, paraphrases, unrelated text), and nothing for the sweep.
- **The loss does not penalise side effects on prompts that fail,** because the KL term is switched on only once the target leads. A failed run therefore ends with a heavily distorted output (KL 2.7 on "Adi"; top-1 changed to "murderer" on the nephew prompt). This is a flaw in the loss as written (inherited from Entry 26 and 27), not tested further.
- **The objective sees one position.** The multipliers are applied at every prompt position, but the tuning scores only the next-token prediction at the last position. Nothing about the continuation of the text is optimised or measured.
- **Single hand-picked prompts, no statistics.** The rows marked * are hand-read from screenshots. Sweep strengths differ between rows. No paired test, no held-out set.
- **One machine, one timing run per row,** no repeats; the sweep time includes its candidate ranking and safety filtering, which gradient descent does not do.

## 9. Decisions taken in this session
- The prototype to be shown to others should show the edit staying on while GPT-2 generates text (the autoregressive behaviour), not only the next word. Planned pieces, none built: (1) a side-by-side view of clean and edited generation, word by word; (2) a per-word trace of target probability, KL against the clean model, and which edited features are active; (3) fact probes with the edit on (the same fact reworded, which should still work; nearby facts, which should not change; CounterFact already holds both kinds); (4) a scoreboard of the sweep against gradient descent on the 300 held-out prompts with the same edit budget (rank-1 rate, KL, paraphrase success, neighbour damage, time).
- Three things to fix first: the loss (penalise side effects also on failing prompts), the objective (tune against reworded versions of the fact and nearby facts so one set of multipliers holds across contexts), and the unequal budget.
- **Instruction tuning of GPT-2 was considered and scrapped:** GPT-2 small is a base model, the whole evaluation (CounterFact) uses completion prompts, and the SAE was trained on the base model's residual stream, so a fine-tuned model would need the SAE re-checked.
- **Kept as future work (documented, not started):** use the gradient-descent multipliers as labels to train the per-feature network (`docs/future_scope.md`).
