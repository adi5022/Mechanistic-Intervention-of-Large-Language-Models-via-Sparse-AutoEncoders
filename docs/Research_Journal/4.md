## 1. Layman's Explanation (The Shift in Paradigm)

### The New Intervention: Weighted Multi-Competitor Muting
In our previous sessions, we focused on muting the model's top competitor one by one in sequence. However, when we muted the top competitor (like `" the"`), a secondary competitor (like `" a"`) would immediately rise to block the correct target, stalling the model's ranking progress.

To solve this, we implemented **Weighted Multi-Competitor Reduction**:
* Instead of fighting the top competitor alone, we identify **all** tokens currently ranked above the target.
* We find the top driving feature for each of these competitors and mute it.
* Rather than muting all features equally, we scale the mute strength in proportion to each competitor's probability. The biggest threat gets muted the hardest, while minor competitors get a lighter touch.

## 2. The Breakthrough Discovery: Shared-Feature Collapsing & Distributed Support

When validating this new method on the **Cambridge** test case, we encountered a fascinating finding that changed our entire understanding of how these grammatical competitors behave in the network.

### The Cambridge Benchmark
* **Prompt**: `"The location of Massachusetts Institute of Technology is in"`
* **Target**: `" Cambridge"` (Clean rank: 8, Clean probability: 1.15%)
* **Above-target competitors**: `" the"`, `" a"`, `" question"`, `" jeopardy"`, `" an"`, `" danger"`, `" doubt"`.

### The Shared-Feature Collapse
When we ran a diagnostic to trace the primary causal feature driving each of these 7 competitor tokens, they collapsed onto only **2 unique features**:

| Competitor Token | Probability | Top Driving Feature ID | Role |
| :--- | :--- | :--- | :--- |
| `" the"` | 17.95% | **313** | Grammatical/Syntax Driver |
| `" a"` | 10.53% | **313** | Grammatical/Syntax Driver |
| `" an"` | 2.63% | **313** | Grammatical/Syntax Driver |
| `" question"` | 7.51% | **21169** | Semantic/Context Driver |
| `" jeopardy"` | 2.71% | **21169** | Semantic/Context Driver |
| `" danger"` | 1.76% | **21169** | Semantic/Context Driver |
| `" doubt"` | 1.21% | **21169** | Semantic/Context Driver |

Because multiple competitors shared the same top driving feature, our max-of-shared-strength rule collapsed the 7 entries into just **2 muted features** with low strengths (0.28 for feature 313, 0.12 for feature 21169). The target rank remained unchanged at 8.

### Key Discovery: The "Loudspeaker" (Distributed Support) Hypothesis
This result reveals a fundamental limitation of the `1 competitor -> 1 feature` hypothesis, especially for grammatical tokens:
1. **Generic Grammatical Directions**: Feature 313 is not a "the" feature, but a generic syntactic direction indicating that a common grammatical word is expected.
2. **Distributed Support**: Common words like `" the"` are supported by many independent features across the network (e.g., 10 different "speakers" playing the same song). Muting only the single loudest feature (turning down 1 speaker) leaves the remaining 9 active, allowing the competitor token to remain dominant.
3. **Research Conclusion**: To successfully suppress distributed grammatical competitors, the intervention model must shift from muting a single representative feature to suppressing a **subspace** of several/all influential driving features for each competitor.

## 3. Technical Implementation Details

### Joint Safety Verification (`check_combination_safe`)
- Tests the entire set of interventions simultaneously in a single forward pass.
- Identifies **new blockers** (tokens that were ranked below the target or absent in the clean top-k but rise above the target post-intervention).
- Excludes original competitors (tokens already above the target in the clean baseline) from the new blocker list to isolate new semantic side-effects.

### Weighted Reduction (`run_weighted_multi_competitor_reduction`)
- Identifies all competitor token IDs ranked above the target.
- Normalizes threat weights: `weight = competitor_prob / sum(all_competitor_probs)`.
- Mutes features with scaled strength: `mute_strength = weight * max_strength`.
- Employs a **maximum-of-shared-strength** rule to avoid over-muting shared features.
- Evaluates the resulting target rank and verifies safety.
