## 2. Theoretical & Algorithmic Foundations

### 2.1 Two-Stage Candidate Selection Mechanics

To evaluate SAE latents efficiently without incurring massive computational overhead, FeatureScalpel utilizes a **2-stage candidate selection pipeline**:

1. **Stage 1: Sparse Activation Screening (1 Forward Pass)**:
   - A single forward pass through the model caches the residual stream vector $x_{\text{residual}} \in \mathbb{R}^{d_{\text{model}}}$ at the final token position.
   - Matrix multiplication via SAE encoder (`sae.encode(last_token_act)`) evaluates all 24,576 latents simultaneously:
     $$\text{feature\_activations} = \text{ReLU}(W_{\text{enc}} \cdot x_{\text{residual}} + b_{\text{enc}})$$
   - Out of 24,576 latents, SAE sparsity (L1/Top-K) renders 99%+ of latents zero. Using `torch.topk`, the system extracts the top $N$ highest non-zero firing latents (e.g. $N = 20$ or $30$).

2. **Stage 2: Causal Ablation Ranking ($N$ Forward Passes)**:
   - Only for the $N$ screened candidates, individual ablation forward passes are executed using delta hooks (`strength=1.0`).
   - The probability drop $\Delta \text{prob} = \text{ablated\_prob} - \text{clean\_prob}$ is computed for target/competitor tokens.
   - Candidates are ranked by causal probability drop.

**Computational Overhead Reduction**:
- Full 24k Ablation: 24,576 forward passes per prompt.
- FeatureScalpel 2-Stage Pipeline: $1 + 30 = 31$ forward passes per prompt (**99.87% reduction in forward passes**).

### 2.2 Delta Patching Formulation & Literature Lineage

When intervening on SAE feature latents, substituting $x_{\text{residual}}$ directly with the SAE's reconstruction $\hat{x} = \text{Decode}(\text{Encode}(x))$ injects the SAE's **reconstruction error** $e = x - \hat{x}$, degrading baseline model performance.

FeatureScalpel implements **Delta Patching** (`src/hooks.py`):
$$\Delta = \text{Decode}(f_{\text{ablated}}) - \text{Decode}(f_{\text{clean}})$$
$$x_{\text{patched}} = x_{\text{residual}} + \Delta$$

#### Primary Academic Citations:
1. **Activation Patching Foundations**:
   - *Meng, K., Bau, D., Andonian, A., & Belinkov, Y. (2022)*. **"Locating and Editing Factual Associations in GPT"** (ROME, NeurIPS 2022). Introduced causal tracing and hidden state activation patching.
2. **SAE Interventions & Reconstruction Error Preservation**:
   - *Bricken, T., Templeton, A., Batson, J., et al. (2023)*. **"Towards Monosemanticity: Global Explanations in a Small Model"** (Anthropic Transformer Circuits). Formalized feature interventions via residual stream delta additions ($x \to x + \Delta$).
   - *Cunningham, H., Ewart, A., Riggs, L., Huben, R., & Sharkey, L. (2023)*. **"Sparse Autoencoders Find Highly Interpretable Features in Language Models"** (EleutherAI / ARC). Demonstrated latent feature steering using difference vectors $\Delta = \text{Decode}(\hat{f}_{\text{mod}}) - \text{Decode}(\hat{f}_{\text{orig}})$.
   - *Templeton, A., Conerly, T., et al. (2024)*. **"Scaling Monosemanticity: Extracting Interpretable Features from Claude 3 Sonnet"** (Anthropic). Scaled delta-based SAE steering hooks to frontier models.

## 3. Empirical Hardware Speed Analysis

An empirical benchmark sweep was conducted using `run_speed_analysis.py` across 3 ROME benchmark prompts (`Dublin`, `Rome`, `Paris`) over 4 layers (`[2, 5, 8, 10]`) with safety filtering enabled (~960 total forward passes).

| **CPU (Host Processor)** | **574.60 seconds** (9.57 min) | **191.53s / prompt** | N/A (System RAM) | 1.00× (Baseline) |
