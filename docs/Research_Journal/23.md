# Research Journal Entry 23: Proposed Update to the Hybrid System, Learned Mute and Boost Strengths (PLAN, not yet run)

**Status:** Planned. Nothing in this entry has been implemented or run. It is written down now so that the attempt is on record whether or not it works.
**Decision owner:** Adi. Claude documents and implements.

## 1. The problem in plain language

The Hybrid Mute & Boost system picks a set of SAE features to turn down (mute) and a set to turn up (boost). The strengths are fixed at the start of a run for every prompt: mute 0.6 and boost 0.5 in the reference setup.

From months of use, the author has seen that changing these strengths changes the outcome. The reason is simple:
- **Too weak:** the target word never gets to rank 1.
- **Too strong:** the edit damages other predictions, the safety filter rejects more features, or a new blocker appears.

A single pair of numbers cannot be right for every prompt. Finding the right pair per prompt by search is slow (each try is a full sweep), and doing that for every new prompt is expensive.

The dynamic safety filter (Entry 21 study) was the first step away from fixed behaviour: it relaxed how the filter judges each feature. This proposal is the same kind of step for the strengths themselves.

## 2. Proposed mechanism

A small network predicts the mute strength and the boost strength for each prompt, in place of the fixed values. Everything else in the pipeline stays unchanged: candidate selection, strict safety filter, cumulative sweep, pool refill.

```
 prompt
   |
   v
 clean forward pass (already done by the pipeline)
   |
   +--> inputs for the network:
   |      - layer-8 residual at the last token (768 numbers), or a few summary numbers from it
   |      - baseline rank and probability of the target
   |      - number of active SAE features, their summed activation
   |
   v
 small network g(theta)  --->  mute strength mu in [0,1]   (sigmoid)
                               boost strength beta in [0, beta_max]  (scaled sigmoid or softplus)
   |
   v
 normal Hybrid sweep, run with mu and beta instead of 0.6 and 0.5
   (candidates -> strict safety filter -> cumulative sweep -> pool refill)
   |
   v
 edited model output
```

Plan: per-prompt strengths first (two numbers per prompt). Per-feature strengths only if per-prompt shows promise. (The dynamic filter's graded mode already scales strength per feature, so that is the natural extension point.)

## 3. How it is trained (Option B, no searched labels)

The edit is a smooth function of the strengths:

`x' = x + sum_{i in M} (-mu) f_i w_i + sum_{j in T} (+beta) f_j w_j`

with M the muted features and T the boosted features. Because of that, the strengths can be trained by gradient descent through the model forward pass, with no dataset of "best strengths" to build.

Steps:
1. **Feature sets come from the reference run.** The reference run (Section 5) records, for each of the 131 prompts, the features that the strict-filter sweep selected (`best_result.mute_features` and `boost_features`). These are used as the training edit sets.
2. **Loss for one prompt.** A hinge on the margin between the target logit and the best competing logit (so it stops pushing once the target is rank 1, like `stop_on_rank1`), plus a penalty on side effects (KL divergence on neutral prompts, using the existing neutral set in `src/hybrid_runner.py`), plus a small penalty on strength size.
3. **Train the network** on a training split of the 131 prompts, tune on a validation split, report on a held-out test split. Split by prompt, stratified by baseline rank. Network kept very small (131 prompts is little data): a linear layer or a two-layer net on a handful of summary inputs, with weight decay. Cross-validation is preferred over a single split.
4. **Use at inference.** Run the network, then run the real sweep with the predicted strengths. The real sweep, not the training relaxation, is what gets measured.

## 4. How it is evaluated (what counts as success or failure)

Compared with the fixed-strength reference run, on held-out prompts only:
- number reaching rank 1,
- final rank on those that do not,
- time per prompt (the network adds one tiny forward pass),
- features used and collateral KL.

Reported as a new arm in the Batch study, like the safety-filter arms. A null result is reported as such.

## 5. Role of the reference run

The reference run (`data/reference_strict_topn200_all.json`) does two jobs:
1. It is the fixed-strength benchmark every other method is compared with (Entry 22 follow-up).
2. Its records supply the feature sets for training the strength network (Section 3, step 1).

Settings: mute 0.6, boost 0.5, Top-N 200, all positions, cumulative sweep, pool refill, strict filter, 250-step cap, layer 8, the 131 prompts with target rank 2 to 1000.

It needs the same environment and the sweep code, not extra VRAM. Each run is a short prompt, so the time is mostly Python and kernel-launch overhead; a bigger GPU does not speed it up much, a faster processor does. It can be run on another machine and the result file copied back (see `handoff.md`). Training the strength network afterwards is small (GPT-2 small plus a tiny network) and fits in 6 GB.

## 6. Known risks, written down in advance

1. **Training relaxation vs the real sweep.** Strengths trained on a fixed feature set may not transfer once the real sweep re-selects features and the safety filter reacts to the new strengths. This is the main risk and the reason the real sweep is what is measured.
2. **Small data.** 131 prompts, partly from shared templates (see Entry 20 and the paper's limitations). Overfitting is likely without a tiny network and a held-out split.
3. **Collapse to a constant.** The network may learn to output nearly the same pair for every prompt. That would still be informative (a better global default than 0.6/0.5) but is not a "learned per-prompt" result.
4. **Optimising probability instead of rank.** The hinge loss is meant to reduce this; the real rank-1 count is the check.
5. **Selection-bias trap to avoid.** Do not tune or select prompts on the test split, and do not compare against the earlier 41/131 or 29/45 figures (different settings).
