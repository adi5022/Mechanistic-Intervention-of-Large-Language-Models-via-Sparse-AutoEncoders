**Date:** October 10, 2026 (late night)

## 1. Why
Import is the original idea of the study: read what the stronger model (medium) knows, translate it into the weaker model's (small's) coordinates and write it into small at inference time, with no weight change and without telling small the answer. The Export work (Entries 32 and 33) did not reach a working method. Before designing Import, the first question is whether medium knows enough true facts that small gets wrong to make a test meaningful at all.

## 2. Method (`tools/transfer/18_import_count.py`, new code only)
Every CounterFact record (21,919; all have a single-token true answer in this project's file) is run through GPT-2 small and GPT-2 medium as it is (no edit, no translator, no SAE). A model "gets it right" when the true answer is its top-1 next word. Prompts of equal token length are batched without padding. Records are sorted into both right, medium right and small wrong (the Import candidates), small right and medium wrong, and both wrong. The ROME dev records (100, `random.Random(0).sample(range(len(ds)), 100)`) and the 30 pilot records are excluded from the counts used for the decision. For the candidates the tool records how far small is from right (the rank of the true answer in small), how sure medium is, and which relations, subjects and answers are represented. The reading rule was written in the plan before the run: 300 or more candidates = worth planning in full; fewer than 100 = a bigger donor or ROME-edited counterfactuals; between = decide with the author. GPT-2 large is not installed, so no donor count for large.

## 3. Results
| | All 21,919 records | Outside ROME dev and pilot (21,789) |
|---|---|---|
| both right | 1,380 (6.3%) | 1,372 (6.3%) |
| **medium right, small wrong (Import candidates)** | **785 (3.6%)** | **780 (3.6%)** |
| small right, medium wrong | 440 (2.0%) | 437 (2.0%) |
| both wrong | 19,314 (88.1%) | 19,200 (88.1%) |

The 780 candidates:
- **How far small is from right:** the true answer is small's second choice for 320, third to fifth for 236, sixth to twentieth for 155, 21st to 100th for 53, below the 100th for 16 (about 71% within the top five).
- **How sure medium is:** median probability for the true answer 0.19; at least 0.3 for 183; at least 0.5 for 54.
- **Variety:** 28 relations (most common P27 105, P37 90, P178 87, P103 73, P176 58, P30 58), 771 distinct subjects, 169 distinct true answers; the ten most common answers cover about 44% of the candidates ('French' 64, 'Apple' 45, 'English' 38, 'Antarctica' 37, 'Islam' 31, 'Russian' 26, 'Microsoft' 23, 'France' 19, 'London' 18, 'Dutch' 17). Only 8 of the 780 are also Export benchmark records.

Rule verdict: 780 candidates against the 300 line -> **IMPORT IS WORTH PLANNING IN FULL.**

## 4. What this does and does not show
- There is enough material for an Import test (780 facts, most of them near misses for small: the true answer is within small's top five for about 71%).
- Medium's own confidence is modest (median probability 0.19), so the signal to be carried is weak for many candidates; the 54 facts it is at least 0.5 sure of are the cleanest cases.
- The answers are skewed towards a few common words (languages, countries, a few companies). A plain push toward a common word could win some cases with no knowledge transferred, so Import needs the same kind of controls as Export (a word-push control, a random-record control, a random-word control).
- NOT shown: that Import works. The translator's medium to small direction fits better than small to medium (R-squared 0.66 against 0.58, stitching 98% against 91%), but in the country-swap control Import gave 33% against 55% for Export, partly because small is the weaker receiver (it knows fewer capitals and often answers with word fragments). Import of real facts has never been tested.
- The reverse set (small right, medium wrong: 437) is a possible control or a mirror experiment.

## 5. Mistakes and corrections
- The first run of the tool failed on an off-by-one in its own length check (the tokenizer in this setup already counts the start token); fixed, no data affected.

## 6. What could be done next (not decided)
Design Import (steps E2 to E4) with the gate, the arms and the controls written in the plan before anything is run: the donor change (medium's translated state against small's own state), small's SAE as the filter, the receiver never told the answer, a split of the 780 candidates into dev and test, controls, and the readings fixed in advance. Alternatives: continue Export with more training edits, a neural map, or amortised D6; or write up what exists.
