## 1. What was built
Version 1 gave all muted features one shared strength and all boosted features another, chosen per prompt (or once for everyone). Version 2 gives **every candidate feature its own multiplier** `m_k = 1 + a_k` (`a_k < 0` mutes it, `a_k > 0` boosts it, `a_k = 0` leaves it alone), from a small shared network ("FeatureNet", `src/feature_models.py`).
- **Input per candidate (27 numbers):** 15 descriptors of the candidate (activation, how many positions it is active at, where it peaks, its removal effect on the target and on the blocker, its direct-logit alignment with the target and blocker, decoder norm, its rank in the mute and boost lists, and the strict filter's verdict at 0.6 / 0.5; `CDESC_NAMES` in `src/strength_models.py`) plus the 12 prompt-level summary numbers. All of this is already in the cache and tables.
- **Network:** 27 to 32 to 32 to 1, the same weights for every candidate (about 2,000 numbers), output limited to `a` in [-1, 2]; starts at `a = 0` for every candidate (no edit).
- **The strict safety filter is not a separate step:** a feature that hurts the target makes the loss worse, so its multiplier is pushed back toward 1 (a "learned filter"). `strict_guard` can additionally drop any feature the strict rule would reject (evaluated as a separate rule).
- **One-shot edit:** all multipliers are applied together (no step-by-step addition, no refill) by adding `sum_k a_k * activation_k * decoder_k` to the saved layer-8 state and running blocks 8 to 11. This is a different mechanism from the sweep, so FeatureNet is compared with the version-1 rules under the same one-shot proxy.
- **Loss:** rank hinge (margin 0.3) + `lam_kl` x KL of the other tokens (only where the target already leads) + `lam_size_feat` x sum |a_k| w_k (w_k = activation share).
- **Scripts:** `tools/train_feature_net.py` (training and all comparisons; `--quick` for a smoke test), `src/feature_models.py`, small additions to `src/strength_models.py` (per-candidate descriptors in `load_item` / `make_batch`; version 1 is unchanged).

## 2. Checks (run every time; the run stops if one fails)
(a) A random per-feature edit through the cache path equals the same edit through your real hook: max logit difference 1.4e-05, same target rank 5 of 5. (b) The saved state reproduces the cached baseline: 5e-08. (c) The untrained network makes almost no edit: largest |a| 0.03 to 0.04.

## 3. Development runs (training size 500 unless stated, 1 seed; validation / test rank-1 on the held-out prompts; one-shot proxy)
The comparison rules in the same proxy (all 450 held-out prompts): reference 0.6 / 0.5 24.9%; version 1 learned pair (mute 0.98 / boost 1.81) 36.9%; version 1 PromptNet 37.8%; version 1 per-prompt tuned 40.4%; **free per-feature multipliers tuned on each prompt: 73.3%** (validation 76.7%, test-seen 68.0%, test-unseen 75.3%, KL of successes 0.35; loss weights lam_kl 10, lam_size_feat 0.05; this is an upper bound for that loss, not a trained model).

**Reading:** a straightforward FeatureNet is above fixed 0.6 / 0.5 (about 25%) but **below the version-1 pair (about 37%)** in this proxy, and far below the free per-feature upper bound (73%). The room per feature is large (the upper bound is nearly twice the per-pool tuned bound), but this network does not capture it yet. It is sensitive to the loss weights (with lam_kl 10 it barely learned) and shows a train-validation gap (about 38% vs 31%), i.e. it is not underfitting by much and is not generalising fully either. Possible reasons, none tested: the per-feature descriptors do not carry the joint effects of many features at once (not measured: how many features the free optimum changes); the network starts from "no edit" instead of from the version-1 rule; the network or the training is too simple.
**Tuning honesty:** the settings were chosen on validation and training results, but the test numbers were printed in the same runs and were visible while choosing; the test numbers of the final run are therefore slightly optimistic.

## 4. Limitations
- Development runs only: one seed, training size 500, four variants; no full run, no learning curve, no paired tests yet (the script prints exact McNemar tests against the version-1 rules and the free upper bound).
- One-shot proxy: no step-by-step addition and no refill; side effects are measured on the one-shot edit (success KL 0.33 to 0.37 here against about 0.9 for version 1's one-shot application of all survivors, which is not comparable because version 1 was designed for the sweep).
- The loss weights for version 2 (lam_kl 3) differ from version 1 (10); differences in side effects therefore reflect a different point on the success versus side-effect curve, not only the model.
- The per-feature multipliers have not been tried in the real sweep (that needs a small extension of `hybrid_runner.py`: a per-feature strength override).
